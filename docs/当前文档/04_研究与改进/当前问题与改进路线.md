# 这个项目下一步最该提高的不是 IR，而是结论可信度

> 中证500多因子项目：问题解决案例与改进路线 · 2026-09-15
>
> 用途：准备“你解决过什么问题”“项目有什么不足”“如果重新做会怎么改”“业绩为什么还不能完全相信”等面试问题。事实依据为[项目事实底稿](../03_面试准备/项目事实底稿.md)和[唯一审计账本](../01_项目治理/学习与审计主线.md)。本文提出的修复与实验是建议方案，除非明确标为“已验证”，否则不代表已经实施。

## 先给结论

这个项目已经具备数据、因子、信号、组合、回测和归因模块，也保存了能够复算的验证结果；当前更重要的问题，是从“模块能够运行”走到“研究结论值得相信”。

最优先的工作有三类：

1. **确认输入在历史时点真实可见。**财务公告与修订、成分生效、行业和 ST 历史覆盖，决定因子是否真正属于当时的信息集。
2. **让目标持仓、实际成交、现金和漂移持仓形成闭环。**否则换手、费用和交易约束可能建立在并不存在的持仓上。
3. **冻结每次实验的完整输入和行为。**当前输出文件能够核对哈希，但尚不能从 run 完整恢复当时的数据、标签、因子定义、代码和环境。

模型和因子研究当然还可以改进，但应排在这三项之后。若底层证据不稳，换成更复杂的模型只会更快地产生一个难以解释的数字。

本文将问题按以下状态区分：

| 状态 | 含义 | 面试中可以使用的动词 |
|---|---|---|
| 已验证 | 已由代码、产物复算或最小案例确认 | 核对、复算、复现、确认 |
| 已定位未修复 | 已知道触发条件和错误行为，但未完成代码修复或影响重估 | 识别、定位、提出修复与验收方案 |
| 合理假设 | 有迹象支持，但尚缺控制变量实验或真实数据核对 | 怀疑、提出假设、计划验证 |
| 未知 | 现有证据不足以判断方向或影响 | 尚不能判断、需要补充证据 |

这四类不能混用。尤其不能将“我知道怎么修”写成“我已经修复”，也不能将“存在缺陷”直接写成“缺陷导致了多少收益”。

## 一、面试中最值得讲的四个问题解决案例

四个案例分别展示不同能力：交易记账、故障安全、配置追踪和可复现性。它们都来自当前项目的实际检查，不需要虚构漂亮的改进幅度。

### 案例一：总资产对得上，不代表锁仓份额没有被错误改变

#### 先用简单语言看懂问题

假设账户里有一只停牌或被锁定、不能交易的股票 A，还用现金买了股票 B。B 的买入会产生费用，但这笔费用只能从现金或可调整的买单中处理，不能让完全没有交易的 A 凭空少掉一部分份额。

当前执行器为使扣费后的总资产对账，会统一缩小全部新份额。这样总金额看起来接近正确，锁仓股票的份额却被改了。问题的本质是：**价值守恒通过了，交易状态守恒没有通过。**

#### 当前证据

最小案例使用总资产 200 元：

- A 原持有 1 份，开盘价 100 元，状态为 `LOCKED`；
- 另有 100 元现金用于购买 B，B 开盘价 100 元；
- B 的买入产生 0.105 元费用。

当前函数将所有份额乘以：

```text
1 − 0.105 / 200 = 0.999475
```

A 最终由 1 份变为 0.999475 份，虽然 A 没有卖出且被记录为锁定。这个行为已经通过合成输入复现；对历史收益的影响尚未量化。具体证据见[事实底稿第 8.2 节](../03_面试准备/项目事实底稿.md#82-已复现交易成本改变锁定份额)和[执行器](../../../src/backtest/engine.py)。

#### 为什么原有测试没有发现

现有测试覆盖了锁仓，也覆盖了交易费用，但没有覆盖二者同时发生的联合状态：一只股票锁仓，另一只股票交易并产生费用。这个案例说明测试覆盖不能只按函数或单一规则计数，还要根据业务不变量组合状态。

#### 正确的修复思路

修复不应简单地“把缩放代码删掉”，而要明确账户方程：

```text
期末现金
= 期初现金
+ 实际卖出所得
− 实际买入金额
− 实际成交费用
```

然后遵循三条原则：

1. 不可交易证券的份额保持不变；
2. 费用从现金扣除；
3. 现金不足时，只缩减允许成交的买单，不缩减锁仓证券或已经完成的卖出。

若采用迭代预估费用，应保证预估与最终实际成交费用收敛并能对账。若费用造成买单缩减，需要记录目标与实际成交差额，而不是事后把目标权重改写成实际权重。

#### 验收标准

修复完成至少需要以下测试：

| 测试场景 | 必须成立的不变量 |
|---|---|
| 锁仓 + 其他股票买入并付费 | 锁仓份额严格不变 |
| 现金足够 | 买入额、费用和期末现金逐项对账 |
| 现金不足 | 只按规则缩减可买订单，现金不为负 |
| 同时买卖 | 卖出所得、买入支出和双边费用方向正确 |
| 全部锁仓 | 无成交、无交易费用、份额不变 |
| 零费率 | 修复前后的可交易份额结果应一致 |

单元测试通过后，还应在获准的训练／验证范围统计：历史上有多少个调仓日同时存在锁仓和其他付费交易、净值变化多大、换手和现金差异多少。不能先假定修复一定使 IR 上升。

#### 面试表达：约 90 秒

> 我在检查回测执行器时发现，一个总资产能够对账的实现仍可能违反交易约束。当前逻辑会在扣除交易费用后统一缩小所有证券份额。我构造了一个两股票案例：A 持有一份且锁仓，账户用现金买 B；B 产生 0.105 元费用后，A 的份额也从 1 变成 0.999475，虽然没有 A 的卖出。
>
> 原有测试分别覆盖了锁仓和费用，却没有覆盖它们同时出现。问题根源是用全资产比例缩放代替账户现金记账。我的修复方案是锁仓份额保持不变，费用从现金扣除，现金不足时只缩减可交易买单，并分别验证份额、现金、成交和费用守恒。目前我已经完成问题定位和最小复现，但还没有修改引擎或重估历史影响，所以不会把它表述成已经提升了业绩。

#### 面试官可能继续问

**问：份额不变，权重为什么还会变？**

因为权重等于证券市值除以总资产。锁仓期间即使份额不变，价格、其他持仓和现金变化都会改变它的权重。执行层应锁份额；优化层可以将相应不可交易市值换算为约束权重，但不能通过虚假交易强行维持一个固定百分比。

**问：这个错误一定高估收益吗？**

不能确定。错误缩减的证券之后可能上涨也可能下跌，方向取决于受影响日期和持仓。当前只确认机制错误，未确认总体收益偏差方向。

### 案例二：数值上“合规”的持仓，可能没有任何有效信号依据

#### 先用简单语言看懂问题

TopN 应该从具有有效分数的股票中选择排名靠前的股票。如果所有分数都缺失，就没有可排序的信息。当前实现只是把 NaN 放到排序末尾，没有真正排除；当全体都是 NaN 时，程序仍可能按列顺序选出股票并返回“合规”。

这里有两个不同的问题：

- **数学合规：**权重非负、总和为 1、数量满足要求；
- **经济有效：**仓位确实由有效信号产生。

当前检查只证明了前者的一部分。

#### 当前证据

三只股票分数全部为 NaN，请求 Top2、单股最大偏离参数为 1 时，辅助函数返回：

```text
[0.5, 0.5, 0.0]
```

同时合规标记为 True。这个最小案例已复现，但尚未证明历史主线实际发生过全 NaN 截面。证据见[事实底稿第 7.1 节](../03_面试准备/项目事实底稿.md#71-主线-topn)和[组合构建代码](../../../src/portfolio/optimizer.py)。

#### 为什么这是生产风险，而不仅是缺失值小问题

如果部分有效分数不足 N，尾部 NaN 股票仍可能被补进持仓；如果全体缺失，选择可能依赖列顺序。列顺序来自数据加工过程而非经济信号，结果可以在文件列顺序改变后无声变化。

更重要的是，信号缺失可能是上游数据或模型故障。此时继续建仓会把技术故障误解释成投资观点。

#### 修复前必须做的业务选择

全缺失时不能由底层函数擅自决定“空仓”“持有原仓”或“回到基准”。三种行为含义不同：

| 选择 | 优点 | 风险 |
|---|---|---|
| 保持实际持仓 | 避免因信号故障主动交易 | 旧持仓可能继续偏离基准，无法自然处理可交易退出 |
| 回到基准 | 降低主动风险 | 仍需要有效交易，信号故障可能触发大额换手 |
| 停止新增交易并报警 | 行为清楚、便于人工判断 | 需要定义已有可卖／不可卖仓位如何处理 |

本文不替项目决定最终策略。更合理的工程设计是：排名函数只处理有限值；上层门禁区分“有效数量不足”“全体缺失”“投资域为空”等状态，并执行经批准的退化规则。

#### 验收标准

- NaN 永远不能凭列顺序进入新选股票池；
- 有效股票少于 N 时，行为由显式配置决定并留下记录；
- 全缺失时返回明确故障状态，而不是普通合规状态；
- 原有锁仓、跌停保留和不可买规则继续生效；
- 对历史信号逐期统计有效数量和退化触发次数；
- 若历史从未触发，不宣称修复提高了历史业绩，只说明增加了故障安全。

#### 面试表达：约 90 秒

> 我检查 TopN 时没有只看权重和是否为 1，而是问这些股票是否真的有信号依据。我构造了三个股票全部为 NaN 的例子，函数仍然返回前两只各 50%，并标记合规。这说明约束合规与信号有效是两种门禁。
>
> 根因是排序只把 NaN 放到最后，没有排除；全空时最终依赖列顺序。修复要先让底层只接受有限值，再由上层明确处理有效股票不足或全缺失。保持持仓、回到基准和停止交易各有风险，需要业务规则确认。我会用历史触发统计判断它是否影响过收益；如果没有触发，就只把它当成可靠性修复，不虚构业绩改善。

#### 面试官可能继续问

**问：为什么不直接填零？**

对标准化因子而言，单个缺失补零是一种“中性值”假设；但最终合成信号全缺失时补零会让所有股票并列，仍然没有选股信息。因子级插补与组合级故障门禁不能混为一谈。

**问：有效股票只有 100 只，但配置要求 Top150 怎么办？**

这是业务退化问题，不应悄悄加入 50 只缺失股票。可以降低持股数、使用经批准的基准补位或保持部分原仓，但必须报告实际持股数、主动风险和退化原因。

### 案例三：配置写着“超额收益”，模型实际读取的可能是原始收益

#### 先用简单语言看懂问题

配置文件表达研究意图，真正决定模型行为的是调用参数和输入缓存。仅检查配置中的 `target="excess_return"`，不能证明 Ridge 确实训练超额收益。

当前阶段调用没有向 Ridge 传入启用超额收益的开关，也没有传基准收益；构造器默认使用原始前向收益。配置、运行行为和缓存标识之间存在不一致。

#### 当前证据

- 主线配置声明目标为超额收益；
- Ridge stage 没有传 `use_excess_return=True`；
- 当前共享标签缓存没有按目标类型版本化；
- 以 2021-01-29 为信号日抽查五只股票，缓存标签与 2021-02-01 到 2021-03-01 的后复权开盘到开盘原始收益精确一致。

这支持“当前抽样标签是原始收益”，但不能反推历史 run 的整个缓存当时完全相同，因为历史输入没有冻结。详见[事实底稿第 6.1 节](../03_面试准备/项目事实底稿.md#61-主线-ridge-的实际算法)、[阶段调用](../../../src/pipeline/stages.py)和[滚动 Ridge](../../../src/signal/ridge_rolling.py)。

#### 为什么影响不能仅凭直觉判断

同一个月内，所有股票的原始收益都减去同一个基准收益，不改变标签排序，所以当月 Rank IC 不变。但 Ridge 把多个月、多个股票放在一起最小化平方误差；各月公共收益、每月因子均值、缺失筛选和月份样本量可能影响拟合。因此两种标签的模型系数和组合结果未必相同。

结论应分两步：

1. 已确认配置没有驱动预期行为，这是工程和研究语义缺陷；
2. 缺陷对历史信号和收益的实际影响，需要同输入控制实验，不能预先宣称夸大或压低收益。

#### 修复与验收方案

1. 把标签类型、价格口径、起止时点和生成版本写入显式标签契约；
2. 标签缓存路径或内容哈希包含契约，不允许原始／超额标签共享一个无版本文件；
3. stage 从配置显式构造标签，配置值未知时立即失败；
4. run 冻结标签文件哈希及生成参数；
5. 单元测试使用带非零基准收益的样本，验证切换配置确实改变数值；
6. 固定因子、窗口、alpha、持仓与费用，比较两种标签的系数、预测排序和净组合结果。

如果最终发现组合排序几乎不变，也不能保留语义冲突。配置行为一致性本身就是可复现要求。

#### 面试表达：约 90 秒

> 我遇到过一个配置与实际运行不一致的问题。主线配置写的是超额收益标签，但我沿调用链检查到 Ridge 并没有收到启用超额收益的开关。之后我抽查五只股票，用两次执行日的后复权开盘价重算，当前缓存与原始开盘到开盘收益一致。
>
> 这说明不能只审配置，还要检查配置是否真正驱动调用和缓存。同月减去相同基准不改变 Rank IC，但 pooled Ridge 跨月份拟合时结果未必不变，所以我不会未经实验就判断收益偏差方向。修复上应把标签类型纳入缓存身份和 run 输入锁，并增加配置行为测试，再用固定输入做原始与超额标签对照。目前确认的是语义和追溯缺陷，不是历史影响幅度。

### 案例四：11 个输出哈希一致，仍然不能证明实验完整可复现

#### 先用简单语言看懂问题

输出哈希回答的是“当前文件是否与记录一致”；完整可复现还要回答“这些文件由哪一版数据、因子、标签、代码、环境和配置生成”。两者不是同一层次。

如果因子定义后来发生变化，而旧 IC 和旧净值仍保存在目录里，只校验输出文件不会告诉我们历史运行使用了哪一版因子。

#### 当前证据

主线 manifest 中 11 个 Parquet 文件的 SHA256 全部匹配；保存 NAV 的八项指标独立复算与原值最大差约 `2.08×10⁻¹⁷`。这证明当前产物内部可核。

但 `inputs.lock.json` 只有 `locked_at`，没有锁定因子面板、财务数据、前向标签、行业、交易状态、因子清单、完整源码和环境。`final_factors.json` 也没有作为 run 内副本冻结。详见[事实底稿第 10.1 节](../03_面试准备/项目事实底稿.md#101-输出可核不等于输入完整锁定)、[主线注册表](../../../registry/mainline.json)与对应 run 目录。

#### 需要建立的实验身份

一次 run 至少应绑定：

```text
研究 Spec 与全部生效参数
  + 代码 commit / 工作区源码哈希
  + Python 与关键依赖版本
  + 原始和处理数据快照身份
  + 投资域、行业、状态快照身份
  + 因子面板与因子定义版本
  + 标签契约与标签文件哈希
  + 最终因子清单及筛选来源
  + 输出清单、哈希、自检和完成状态
```

仅记录 Git commit 仍可能遗漏未提交文件和外部数据；仅记录路径也可能在文件被覆盖后失效。应优先使用不可变快照或内容哈希，并记录重建步骤。

#### 发布门禁也需要修正

当前运行流程还存在：manifest 失败只记录 warning、先写完成标记再做部分自检、晋升主要检查文件存在等问题。一个可靠门禁应满足：

- 输入身份不完整则不允许运行或晋升；
- 关键校验失败则 run 状态为失败，不写正式完成标记；
- 临时输出在所有检查通过后原子发布；
- 历史产物不可被同路径静默覆盖；
- 自检结果和 fallback、缺失、覆盖统计随 run 保存。

#### 面试表达：约 90 秒

> 我对主线做过两层复核：第一层是 11 个输出文件哈希与 manifest 一致；第二层是从保存 NAV 独立复算八项指标，数值一致。这能证明当前结果文件内部可核。
>
> 但继续检查发现，输入锁只有时间戳，没有冻结面板、标签、因子清单、代码和环境。因此“输出一致”不能升级成“完整可复现”。我的改进方案是为每个 run 绑定数据、标签、因子、代码和依赖的内容身份，并让校验失败阻断完成和晋升。这个案例让我认识到，可复现不是多存几个结果文件，而是能从实验身份追到每一个决定结果的输入。

## 二、另外三个重要问题：适合回答“项目还有什么不足”

这三个问题很重要，但当前证据不适合包装成已经解决的 STAR 案例。

### 1．真实 PIT、成分与状态历史尚未闭环

**已确认：**代码实现 `pit_date <= T` 和 TTM 构造；历史审计记录早期行业未分类比例高、ST 覆盖起点晚；成分权重日期尚未与正式生效公告对账。

**尚未知：**这些缺口对 18 个因子、最终持仓和验证收益分别影响多少。

**为什么优先级最高：**如果输入本身在历史时点不可见，后续统计显著性、Ridge、风险优化和回测都失去解释基础。

**面试表述：**

> 我已经实现公告日期驱动的 PIT 查询和合成边界测试，但真实公告修订、成分生效和状态历史尚未全部人工闭环。下一步会按股票和年份分层抽样，追到原始公告与供应商记录，再用“追加未来修订不改变过去查询”的不变性测试验证接口。

### 2．目标权重没有闭环为下一期真实持仓

**已确认：**主线 106 期元数据中的上期权重来源是 `target_weight`，不是执行后漂移持仓。

**可能影响：**换手、单股约束、锁仓、成分退出和优化惩罚可能建立在未实际形成的仓位上。

**尚未知：**目标与实际持仓差异的历史分布、对净值与 TE 的影响。

**面试表述：**

> 组合层需要区分 T 日目标、T+1 成交份额和下一调仓前的漂移权重。当前主线把上期目标作为下一期输入，闭环不足。我会以实际份额和当期执行价格重建权重，并逐期对账目标、成交、未成交、现金和漂移。

### 3．主线归因没有与净回测形成独立对账

**已确认：**行业归因和因子归因代码及单元测试存在；本主线目录没有完整对应归因产物。

**不能声称：**9.35% 年化超额主要来自某个因子或行业；残差就是纯 alpha；45.77% 是优化器吞掉的真实超额。

**应补的证据：**同一 run、同一实际持仓、同一收益区间下，依次连接毛收益、行业／因子解释、现金、费用、基准重构差和最终净主动收益。

## 三、改进路线：先修研究可信度，再比较模型

### 路线总览

```text
阶段 A：输入可信
  PIT / 成分 / 行业 / ST / 下载与发布门禁
          ↓
阶段 B：交易可信
  目标 → 成交 → 份额 → 现金 → 漂移持仓
          ↓
阶段 C：实验可追溯
  数据、标签、因子、代码、配置、环境共同冻结
          ↓
阶段 D：统计与模型比较可信
  嵌套时间验证、简单基线、因子增量、参数稳定性
          ↓
阶段 E：净收益归因与部署判断
  毛收益、风险暴露、费用、现金、基准差异完整连接
```

阶段之间不是说上一阶段所有细节必须完美，才允许写下一行代码；含义是后续结论不能超过上游证据。例如可以开发归因代码，但在持仓和输入未闭环前，不能把归因数字称为可信收益来源。

### 阶段 A：让每条输入都能回答“当时真的知道吗”

#### A1．真实公告和修订抽样

**行动：**按年度、行业、盈利／亏损、正常／修订、多报表来源分层选取 5—10 只股票及若干报告期；保留原始记录、公告链接或供应商返回、报告期、公告日、版本和值。

**检查：**

- T 在首次公告前查询不到该版本；
- 首次公告后、修订前得到旧值；
- 修订后得到新值；
- 向数据库追加未来版本不改变过去 T 的查询；
- TTM 三个组成项均能追到当时可见来源。

**完成标准：**不是“抽样全部正确”一句话，而是保存样本表、期望值、查询结果和差异原因；无法确认的记录显式标记，不用后来的值补齐。

#### A2．成分生效、行业和状态覆盖

**行动：**将公告日、供应商 `trade_date` 和正式生效日分开；按调仓日恢复当期指数域。对行业和 ST 按年份统计覆盖率，并检查金融股排除是否因行业缺失失效。

**完成标准：**每个调仓日都能说明成分来源和生效规则；未知行业、ST、新股、停牌不是静默填成正常状态；覆盖不足能阻断或触发批准的退化。

#### A3．数据下载与正式发布门禁

**行动：**下载状态区分“成功有数据、成功无数据、失败”；写入临时文件，经过键唯一、字段、范围、覆盖和金融逻辑检查后再原子发布。断点续传不能只看文件存在。

**完成标准：**通过故障注入验证超时、空表、部分年份缺失、重复键和单位异常都不会成为正式输入；失败产物不会被 resume 视为完成。

### 阶段 B：让组合约束真正作用在账户状态上

#### B1．修复费用与锁仓份额

按案例一实施。完成标准不是净值能跑，而是每期账户方程、锁仓份额、费用方向和现金余额分别守恒。

#### B2．建立有效信号门禁

按案例二实施。除全 NaN 外，还需统计每期有效因子数、有效股票数、行业覆盖和被补零比例。门禁状态随 run 保存。

#### B3．回传真实持仓

执行器应输出实际成交、未成交、份额、现金和日终权重。下一调仓日由份额与价格计算漂移权重，作为换手与交易约束输入。

**逐期对账表应至少包含：**

| 对象 | 需要保存的内容 |
|---|---|
| 目标 | 目标权重、生成原因、信号版本 |
| 订单 | 目标差额、状态限制、计划方向 |
| 成交 | 实际数量、执行价近似、费用、未成交原因 |
| 账户 | 证券份额、现金、净资产 |
| 下一期输入 | 漂移权重及其来源日期 |

#### B4．审计开盘时点的交易状态

检查涨跌停、开板次数和停牌状态在 T+1 开盘是否已可见。若日频数据无法支持精确撮合，定义保守近似并做敏感性分析；不使用当天收盘后信息决定开盘成交。

### 阶段 C：让任何结果都能回到唯一实验身份

#### C1．统一输入清单

将数据、面板、标签、投资域、状态、因子清单和代码身份写入不可变 manifest。共享缓存必须包含生成契约，不能由不同目标或日期口径复用。

#### C2．让配置真正驱动行为

对关键配置写行为测试，而不只检查字段存在：

- `target` 改变时，生成的标签按定义改变；
- `optimizer_mode` 决定实际调用 TopN 或优化器；
- 基准标识对应全收益数据；
- 印花税在规定日期切换；
- 未支持的参数组合立即失败。

#### C3．发布状态后置且阻断

只有 manifest、数据门禁、关键诊断和自检全部通过后写完成状态。关键失败不能只 warning；正式产物和临时产物隔离，避免先发布后发现错误。

### 阶段 D：减少研究自由度，重新判断模型有没有增量

#### D1．建立简单而可信的基线

至少保留因子等权、历史 IC_IR 加权和 Ridge 三类。全部使用同一数据、日期、缺失、持仓与费用。基线的意义不是必须击败 Ridge，而是回答复杂模型增加了什么。

#### D2．嵌套时间评价

对每个外层评价区间，仅在此前训练区间内完成因子筛选、方向、alpha 和窗口选择；外层只评价。不能随机拆分同月股票，也不能将训练全期选出的 18 个因子当作每个早期折都已知。

**完成标准：**保存每个外层折的候选清单、入选因子、参数、训练截止、标签退出日和评价结果；汇总所有尝试，包括失败模型。

#### D3．因子组增量与稳定性

优先按经济家族做消融，而不是逐列删除后把相关因子的替代效应误认为无用。比较加入候选前后的配对月份：预测排序、净超额、TE、换手和风险暴露。

特别需要核查：

- 北向因子 2016 年后才有有效覆盖，前后特征空间不同；
- Piotroski 为七项简化版，缺项可比性不足；
- 收入加速度未先拆单季；
- `roe_delta_3q` 在缺季时可能不是严格三个季度；
- EPS 修正未固定同机构、同目标财年；
- Ridge 没有使用筛选阶段的 0.5/1.0 稳定性权重。

#### D4．重新判断 alpha 和窗口

当前 alpha=5000 位于网格上端，需要看评分曲线是否平坦、是否由单一时间折主导、系数与预测是否接近零。扩大网格不是自动答案；所有扩展在训练内完成。

48 个月、expanding 和衰减 expanding 的比较，应固定其余条件并报告不同市场阶段的稳定性。窗口选择不能只看一个汇总 IR。

### 阶段 E：回答“收益究竟来自哪里”

#### E1．先完成独立净值桥接

逐期建立：

```text
股票毛收益
− 交易费用
+ 现金收益
= 策略净收益

策略净收益
− 官方全收益基准收益
= 净主动收益
```

成分权重重构基准与官方指数的差异单列，不能用前者无声替代后者。

#### E2．再做行业和因子解释

行业归因使用一致的期初实际持仓和收益区间；现金作为明确资产或独立项。因子归因中区分因子暴露、当期因子收益和预测系数。

**完成标准：**归因结果能逐期连接独立净值；费用、现金、基准差和残差分别可见。会计闭合是必要条件，但仍不意味着因果解释成立。

#### E3．最后讨论策略改进

若行业偏离贡献大，先判断是有意承担的风险还是数据／组合映射造成；若费用侵蚀大，先定位阈值换手、成分变更还是未成交；若因子贡献衰减，先排除定义和覆盖变化。每次只改变一类机制，并提前写好支持或否定假设的结果。

## 四、当前业绩的缺憾和原因，怎样回答才专业

### 已经观察到的结果

2021-01-04 至 2022-12-30 的保存验证结果可复算：策略年化收益约 5.85%，全收益基准约 −3.50%，二者 CAGR 之差约 9.35%，TE 约 4.35%，项目口径 IR 约 2.15。策略绝对最大回撤约 24.88%，相对净值最大回撤约 3.03%，年化双边换手约 7.22 倍。

这些数字说明在该两年历史记录中，策略相对基准表现较好且换手落在项目目标范围；它们没有证明收益能够长期持续。

### 可以确认的缺憾

1. **绝对风险并不低。**相对回撤小不能替代约 24.88% 的绝对回撤。
2. **评价期较短。**两年只覆盖有限市场状态，月收益观测也有限。
3. **验证并非完全独立。**窗口、TopN 等有验证比较历史，因子和超参数选择又没有完整嵌套。
4. **输入与执行证据未闭环。**PIT、成分、真实持仓、费用和输入版本均有未决项。
5. **信号显著性证据有限。**历史诊断的合成信号 IC t 值约 1.61，历史比较 p 值约 0.12；这不是组合 IR 的显著性，但也不能声称信号已在常用 5% 水平显著。
6. **收益来源尚未完成同 run 归因。**不能确认超额主要来自哪些行业、因子或无意风险暴露。

### 原因分析必须分成三层

| 层次 | 本项目示例 | 可以如何表述 |
|---|---|---|
| 已确认机制 | 锁仓份额会被统一扣费缩放 | 当前实现违反份额守恒，影响方向尚未量化 |
| 有证据支持的风险 | 目标权重代替真实持仓；输入未完整冻结 | 换手和结果追溯可能失真，需要逐期对账 |
| 待检验假设 | TopN 的行业／风格暴露、少数月份贡献、北向覆盖变化 | 可能解释表现，但不能称为已证实根因 |

### 面试中推荐的完整回答

> 当前结果最大的缺憾不是 IR 不够高，而是还不能把这段超额完全归结为可实施、可泛化的选股能力。第一，绝对最大回撤约 24.88%，相对回撤 3.03% 不能代替投资者实际承受的风险；第二，验证只有两年且参与过部分研究选择；第三，PIT、真实持仓闭环和输入版本还有未决问题；第四，主线缺少与净值一致的归因产物。
>
> 我能确认的是这些风险和两个最小反例，尚不能确认 9.35% 超额有多少由某个问题造成，也不能说主要来自某个行业或因子。改进顺序是先把输入和执行对账，再做嵌套时间验证和同 run 归因，最后才判断需要换因子、改 TopN 还是增加模型复杂度。

### 不专业的回答方式

- “2021—2022 市场不好，所以绝对回撤大。”这只是可能背景，没有量化 beta 和回撤贡献。
- “QP 把 alpha 吃掉了。”现有 45.77% 指标不是严格净超额损失，主线 V1/V2 也不是有效对照。
- “北向因子失效导致后面表现差。”没有当前主线完整归因和制度分段实验。
- “Ridge 太简单，所以需要 XGBoost。”模型复杂度与已发现的数据、状态问题无直接对应关系。
- “测试都通过，所以只是小问题。”现有 101 项是六个文件的合成测试，不包括真实公告核对和全部联合状态。

## 五、如果面试官给你一个限定时间，怎样安排

以下是优先顺序示例，不是已经执行的项目计划，也不承诺具体工期。实际安排取决于原始数据可得性和修复范围。

### 如果只能做一件事

建立一套可复查的输入身份，并完成真实 PIT／成分样本核对。原因是它决定所有下游结果代表的究竟是不是历史可获得信息。

### 如果只能处理三个问题

1. 冻结和核对数据、标签、因子与代码输入；
2. 修复锁仓费用、缺失信号和实际持仓回传；
3. 用冻结输入重建简单基线，并完成净值到归因的逐期对账。

### 如果被问“给你两周会怎么做”

可以按四个可交付结果回答，而不是许诺把所有问题解决：

1. **数据证据包：**5—10 只股票的公告／修订／TTM 手工核对，成分生效及行业／ST 分年覆盖表。
2. **执行修复包：**锁仓付费与全 NaN 的失败测试、最小代码修复、账户不变量测试，以及目标—成交—漂移对账样例。
3. **实验身份包：**完整 inputs manifest、标签契约、配置行为测试和阻断式完成门禁。
4. **影响报告：**只在获准的训练／验证范围对修复前后做控制对照，报告净值、换手、TE、触发次数和仍未解决的问题。

如果原始公告或历史状态数据无法取得，应把对应验收标记为阻塞，而不是用当前处理数据自证正确。两周计划的专业性来自清晰交付和停止条件，不来自任务数量。

## 六、把这些案例写进简历时的边界

当前最稳妥的简历句子是：

> 通过净值复算、调用链追踪与边界案例检查研究结果，识别锁仓扣费改变不可交易份额、全缺失信号仍生成持仓以及标签配置未生效等问题，并设计账户守恒、信号门禁和实验输入冻结的修复与验收方案。

这句话能体现问题解决能力，又没有谎称已经完成修复。若未来真正完成代码修复、测试和影响重估，才可以改为：

> 修复〔具体问题〕，补充〔具体联合测试〕并在〔明确样本范围〕复核影响；修复后〔只填写真实、已验证的指标或行为变化〕。

不要提前预留“显著提升 IR”“降低回撤”等结果。修复的首要价值可能是降低不可信的历史表现，而不是让数字更漂亮。

## 七、面试前自测：你是否真正理解这些改进

不看文档回答，每题控制在一分钟：

1. 为什么总资产守恒不能证明回测交易正确？
2. 锁仓时应锁定份额还是权重？为什么？
3. 全 NaN 信号为什么可能按列顺序产生持仓？
4. 信号故障时为什么不能由底层函数擅自回到基准？
5. 配置写超额收益，为什么还要核对模型调用和缓存？
6. 同月减基准为何不改变 Rank IC，却可能改变 pooled Ridge？
7. 输出文件哈希一致与完整可复现有什么区别？
8. 为什么真实 PIT 核对要同时覆盖首次公告和后续修订？
9. 目标权重、成交份额和漂移权重分别是什么？
10. 为什么在修复执行器前不应急着比较新模型？
11. 归因算术闭合为什么不能证明收益来源解释正确？
12. 当前业绩哪些是观察，哪些原因仍是假设？
13. 修复后 IR 下降，你如何判断修复是否值得保留？
14. 如果历史从未出现全 NaN，相关修复还有没有价值？
15. 你会用哪三个验收标准判断项目从研究原型向可靠回测前进了一步？

推荐的最后一题答案是：历史时点输入可追溯且可见；实际账户与交易状态逐期守恒；任何结果都能绑定唯一输入并由独立净值与归因对账。模型表现是重要评价，但不应替代这三项底线。
