5. **研究定型前不读取测试集结果来选因子、调参数或选择模型。**

本文件既是阅读路线，也是检查清单和阶段进度账本。以后每完成一个阶段，应直接更新本文件第 15 节的状态，不另建第二套总路线。

## 4. 每个阶段统一采用的学习—审计循环

以后阅读任何一个模块，都按以下八步进行：

1. **金融目的**：它解决什么投资研究问题，为什么需要它。
2. **时间轴**：T 日能看到什么，标签在哪一天，交易在哪一天。
3. **输入契约**：文件、索引、字段、dtype、单位、缺失值含义。
4. **代码路径**：入口函数、核心函数、降级路径、异常路径。
5. **最小手算**：用 2～5 只股票、2～4 个日期构造可人工核对的例子。
6. **测试证据**：现有测试覆盖什么；缺少的失败用例先补测试。
7. **真实数据抽查**：只在训练/验证范围内做小样本核对。
8. **阶段结论**：PASS / PASS WITH CAVEAT / FAIL，并更新第 15、16 节。

未经第 5～7 步证明，不能因为函数有 docstring、测试数量多或历史报告漂亮就判定通过。

- 理解 API 参数日期与最终可用日期不是一回事。
- 理解断点续传、主键去重、限频和失败重试。

### 代码阅读顺序

1. `src/config.py`
2. `scripts/download_tushare.py`
3. `scripts/download_supplement.py`
4. `scripts/download_alternative_data.py`

### 当前真实下载分组

- 基础下载：成分股权重、股票基础、名称变更、行业、指数、日行情、复权因子、daily basic、停牌、涨跌停、财务。
- 补充下载：融资融券、资金流、股东户数、分红。
- 另类下载：港股持仓、分析师预期、限售解禁、股东增减持、筹码、质押、沪深港通、龙虎榜、机构榜、盘后大宗、机构调研、主营构成。

### 核心检查

- `ts_code` 是否始终含交易所后缀。
- 后复权价格的构造能否从原始 close + adj factor 被手算复现。
- 中证500全收益指数代码是否在下载、转换和回测三处一致。
- 成分股权重是生效日快照还是公告日记录。
- 各接口字段单位是否显式记录，特别是市值、股本和资金流。
- 原始 CSV 的主键、重复记录、覆盖起止、失败股票清单是否完整。
- API 返回空表时，是合法空值还是下载失败。

### 完成门槛

- 形成“接口 → 原始文件 → 主键 → 日期字段 → 单位 → 下游用途”数据字典。
- 随机抽取至少 5 只股票和若干日期核对原始记录。
- 下载失败不会被静默当作零值或正常缺失。

## 8. 阶段 3：PIT、成分股与交易状态

### 代码阅读顺序

1. `src/data/pit_loader.py`
2. `src/data/loader.py` 中各类 `*_pit` loader
3. `src/data/universe.py`
4. `tests/test_pit.py`
5. `tests/test_alt_data_pit.py`
6. `tests/test_universe.py`

### 必须掌握

- `ann_date`/`pit_date` 是“何时可知”，`end_date` 是“数据描述哪个报告期”。
- TTM、单季度值、同比/环比值如何处理累计财报。
- 财报修订时怎样在 T 日选择当时可见的最新版本。
- 指数成分股、生效日、ST、新股、停牌、涨跌停如何共同决定投资域与交易状态。

### 核心检查

- 所有财务可见性满足 `pit_date <= T`，并验证报告期边界。
- 不允许用最终修订值覆盖历史上当时可见的旧值。
- 成分股按生效日而非公告日对齐。
- 上市不足 180 天、ST、停牌显式标记，不由缺失值隐式代表。
- 状态数据缺失采用保守路径，并记录覆盖率。
- “不可进入投资域”和“已有持仓无法交易”不能混为同一个动作。

### 强制人工核对

- 抽取 5～10 只股票，选择年报、一季报、半年报、三季报各至少一个边界日期。
- 对每个样本记录 T 日可见的公告版本、报告期、进入因子值的过程。
- 抽取至少一个停牌、涨停、跌停、ST、新股案例核对状态。

### 完成门槛

- 人工核对表与自动测试同时存在并一致。
- 任意一个 T 日截面都能回答“这条记录为什么此时可见”。

## 9. 阶段 4：因子构建与截面预处理

### 代码阅读顺序

1. `src/factors/financial_factors.py`
2. `src/factors/price_factors.py`

4. `src/factors/preprocess.py`
5. `scripts/build_factor_panels.py`
6. 因子相关测试

### 学习方法

为每个候选因子建立一张“因子卡片”：

- 经济含义与预期方向
- 数学公式
- 原始字段与单位
- 回看窗口
- T 日时间边界
- 金融行业是否适用
- 缺失值处理
- 去极值、中性化和标准化顺序
- 相关测试与已知风险

### 核心检查

- 因子函数读取行情的终止日期不得晚于调仓日 T。
- 未来收益变量必须以 `future_`/`fwd_` 命名，只能作为标签。

- 中性化使用行业哑变量和 `log(free_float_mcap)`，不能换成流通市值或总市值。
- 金融股财务因子的特殊处理必须可见、可测试。
- 不用未来截面的可用性来反向筛选历史股票。
- 因子方向、缺失填充和 winsorize 顺序不能散落在多个入口中互相覆盖。

### 完成门槛

- 每个正式候选因子有因子卡片和至少一个边界测试。
- 逐因子执行 shift/时间边界检查。
- 构建脚本的实际因子集合以代码常量为准，不再相信旧文档中的固定数量。

### 核心检查

- 交易成本基于实际成交额，而不是未成交的目标差额。
- 现金、权重归一化、舍入误差和持仓漂移可对账。

### 强制手算

至少构造两个完整调仓周期，包含：

- 正常买卖；
- 印花税切换日前后；
- 一只涨停、一只跌停、一只停牌；
- 一只缺失开盘价；
- 部分成交后的现金与实际权重。

### 完成门槛
