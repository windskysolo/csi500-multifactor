## 0. 先给结论

这一阶段的主干设计是正确且容易解释的：在调仓日 `T` 先取得当期可投资域，分别构造财务、量价和另类数据因子的原始横截面，再在 **T 日横截面内部**执行金融行业过滤、MAD 去极值、标准化、行业与自由流通市值中性化、残差再标准化，最后把每个因子保存为 `rebalance_date × ts_code` 面板。

代码中以下做法值得保留：

- 价格使用后复权口径，窗口以真实交易日定位；
- 财务因子通过 PIT loader 读取 `pit_date <= T` 的信息；
- 去极值边界只由当期横截面计算；
- 中性化明确使用 `log_free_float_mv`，没有误用总市值；
- 缺失值在预处理阶段保持为 `NaN`，单因子检验再 `dropna`；
- 因子失败相互隔离，并保存了覆盖率和中性化诊断；
- 默认构建截至验证期，测试期需要显式开门并使用独立面板目录。

但按工业级门槛，本阶段当前结论是 **FAIL，不是代码完全不可用，而是证据链尚不足以证明产物可信**。最重要的原因有：

1. 因子计算异常会被捕获并写成全 `NaN`，脚本仍成功结束；而完整性检查只看日期是否存在，失败截面可能被永久当成“已完成”。
2. 测试期面板虽然隔离，诊断文件却固定写入训练/验证共用路径；现有诊断已经混入 2023—2025 年记录。
3. 2012—2013 年大量行业被编码成 `999999.SI`，中性化把它当成一个真实行业，而不是缺失数据。
4. `--resume` 不能可靠补齐历史中间缺口。
5. 当前 125 项测试通过，但没有逐因子完成真正的时间扰动测试；现有一个所谓 `shift(-1)` 负例移动的是股票顺序，不是时间。
6. IVOL、RSI、融资流量等位置存在“缺数据等于零收益/零流量”的语义混淆。
7. 注册表共有 58 个正式可构建因子，历史评价覆盖 55 个，超过项目规定的 20—30 个候选范围，尚缺少事前研究假设和扩池理由。

所以正确表述不是“因子代码没问题”，而是：

> 因子公式与截面处理主框架基本成立，合成测试也较完整；但失败传播、产物隔离、早期行业数据和逐因子时间边界证据仍未闭环，因此现阶段只适合继续研究和教学，不应把现有面板直接视为生产级可信输入。

## 1. 这一阶段在完整流水线中的位置

上一阶段解决的是：在调仓日 `T`，哪些股票可投、哪些信息已经可见、哪些股票存在停牌/ST/涨跌停状态。

本阶段解决的是：对每只可投股票，把原始数据变成可以横向比较的因子暴露。

完整链条是：

```text
processed 原始数据
    ↓
T 日可投资域 U_T
    ↓
原始因子 x_raw(T, i)
    ↓
金融行业适用性过滤
    ↓
T 日横截面 MAD 去极值
    ↓
T 日横截面 Z-score
    ↓
行业 + log(自由流通市值) 中性化
    ↓
残差再 Z-score
    ↓
单因子面板 factor_panels/{factor}.parquet
    ↓
下一阶段：用 T 日因子解释 T→T+1期未来收益，做单因子评价
```

这里必须区分三个时间：

- `T`：调仓日盘后，信号允许使用截止 `T` 已知的信息；
- `T+1` 交易日开盘：策略实际成交；
- `future_ret(T)`：评价标签，只用于下一阶段检验，绝不能反向进入本阶段因子。

面试中的一句话回答：

> 因子层把异构原始数据变成同一调仓日上可比较、可合成的截面暴露；标签属于评价层，成交属于回测层，三层必须通过时间边界解耦。

唯一阅读顺序如下：

1. `src/factors/financial_factors.py`：理解 PIT 财务快照、TTM 和同比构造。

## 3. 从一次调仓日看实际调用链

以某月末调仓日 `T` 为例，`build_panels()` 的实际动作如下。

### 3.1 确定运行日期

```python
full_dates = get_rebalance_dates(start=TRAIN_START, end=VALID_END)
```

默认只构建 2012—2022 的训练和验证期。日期来自交易日历/成分数据，不是假设每月最后一个自然日。

### 3.2 取得 T 日可投资域

```python
codes = get_investable_universe(T)
```

这里已经应用上一阶段的成分股、上市时长、ST 和停牌等规则。因子函数只对 `codes` 计算，不能用今天的股票池回填历史。

### 3.3 提取中性化解释变量

```python
industry_day = industry_df.xs(T)["industry_code"].reindex(codes)
log_mv_day = basic_df.xs(T)["log_free_float_mv"].reindex(codes)
```

关键口径：

- 行业：申万 2021 一级行业；
- 规模：`log(自由流通市值)`；
- 两者必须与因子共享同一个 `T` 和同一批 `ts_code`。

### 3.4 构造三类原始因子

```python
raw_fin = build_all_financial_factors(T, codes)
raw_price = build_all_price_factors(T, codes)
raw_alt = build_all_alt_factors(T, codes)
```

三类函数都只返回原始值，不在函数内部进行统一 Z-score 和行业中性化。这个边界是好的：公式构造与横截面处理分离，便于单测和复用。

### 3.5 逐因子预处理

财务因子传入金融行业代码集合，量价和另类因子不传：

```python
processed = preprocess_factor(
    raw=raw_aligned,
    industry=industry_day,
    log_mv=log_mv_day,
    fin_sector_codes=FINANCIAL_SECTOR_CODES if is_financial else None,
)
```

### 3.6 落盘

每个因子成为一个宽表：

```text
index   = rebalance_date
columns = ts_code
value   = 预处理后的因子暴露
```

这种格式适合下一阶段逐日取横截面，也容易保存为 Parquet。当前主目录共有 61 个历史面板文件，其中包括已从当前注册表移除的旧因子；当前代码实际注册 58 个因子。

## 4. 财务因子：如何从 PIT 报表变成横截面信号

### 4.1 共同时间逻辑

财务因子的共同入口不是“取报告期小于 T 的最新报表”，而是：

```text
先筛 pit_date <= T
→ 同一股票、同一报告期保留 T 时点可见的最新版本
→ 再按报告期选择最新期或拼接 TTM/历史季度
```

这避免把尚未公告的财报提前放入回测。需要继续继承上一阶段的 caveat：同日公告缺少具体时间时，`pit_date == T` 是否能用于 T 日收盘信号仍需保守定义。

### 4.2 TTM 为什么不能直接拿最新季度累计值

A 股利润表和现金流量表多数是年内累计口径。例如三季报净利润是 1—9 月累计，不能直接与另一家公司年报的全年值比较。

常用 TTM 拼接为：

```text
TTM(T) = 本期累计值 + 上一完整年报值 - 上年同期累计值
```

如果当前可见的最新报告就是年报，TTM 可以直接取年报值。所有参与拼接的版本都必须在 `T` 日可见。

### 4.4 财务因子的行业处理

构建脚本把上述所有 `FINANCIAL_FACTORS` 在银行和非银金融行业置为 `NaN`。其优点是简单、保守，避免银行资产负债率、保险现金流和普通工商企业混比。

它的代价是：金融股仍可留在指数投资域中，但不从财务因子获得横截面 alpha，后续填零时相当于财务维度中性。更精细的业界方案包括：

- 按行业设计不同公式；
- 金融行业内部单独标准化；
- 对金融股只启用有可比意义的指标；
- 把“适用行业集合”写入因子元数据，而不是依赖因子名属于哪个 Python 列表。

本项目当前的全过滤方案可以作为保守基线，但必须在模型解释中说明。

## 5. 量价因子：窗口、复权和缺失值

### 5.1 交易日窗口

代码从 `index_quote.parquet` 读取真实交易日：

```python
valid = all_dates[all_dates <= T]
```

这比 `T - 60 calendar days` 更正确，因为春节、国庆和临时休市会导致自然日窗口包含的观测数不稳定。

累计收益不通过逐日收益连乘，而通过后复权价端点比值：

```text
cum_ret = close_adj[end] / close_adj[start] - 1
```

这样不会因中间某天缺行而少乘一个收益率，但仍要求两个端点都存在。

### 5.3 为什么后复权很重要

如果收益率使用不复权价格，分红送转除权日会被识别成巨大负收益；如果不同因子混用前复权和后复权，历史端点会被不同基准缩放。项目规定全程使用后复权价和后复权收益率，因子只关心相对收益，不把公司行动误当价格信号。

### 5.4 IVOL 的实现与当前缺陷

代码使用向量化 OLS：

```text
r_i,t = α_i + β_i r_m,t + ε_i,t
IVOL_i = std(ε_i,t)
```

向量化一次计算所有股票，速度优于逐股回归。但代码把 `ret_pivot` 中所有缺失值填为 0。只有当缺失明确代表停牌且停牌日经济收益设为 0 时才合理；若缺失来自下载失败、上市前或代码未覆盖，填 0 会人为压低波动率并改变 beta。

业界更稳妥的做法：

- 先用交易状态区分停牌与数据缺失；
- 对每只股票在有效的 `(stock_ret, market_ret)` 交集上回归；
- 要求最少有效日数和覆盖率；
- 输出有效观测数、beta 和回归残差诊断。

| `analyst_cnt_chg` | 近期机构数−远期机构数 | + | 新覆盖与数据源扩容可能混淆 |
| `float_pct_30d` | 已公告且未来 30 日解禁比例 | − | “无事件=0”只在源数据完整时成立 |
| `insider_net_buy` | 90 日高管/股东净增持比例 | + | “无事件=0”只在源数据完整时成立 |
| `pledge_ratio` | 最新股权质押比例 | 通常 − | 原表无公告日，按报告期进入会有前视风险 |

另外，`chip_winner_rate`、`cost_deviation` 和 `north_flow_5d` 仍有历史面板/诊断，但已从当前注册表剔除。特别是 `north_flow_5d` 对所有股票广播同一个值，横截面没有区分度，标准化会退化为全 `NaN`。

### 6.2 无事件与无数据不能混为一谈

`float_pct_30d` 和 `insider_net_buy` 在没有记录时填 0，隐含前提是：数据源完整覆盖所有股票，确实没有事件。

如果下载失败、接口起始日期较晚或某股票未覆盖，0 就会把“未知”误标为“确定没有事件”。工业级数据应至少有：

```text
value          事件值
is_covered     数据源是否覆盖该股票和日期
has_event      覆盖范围内是否发生事件
available_at   事件何时可见
```

只有 `is_covered=True and has_event=False` 才能安全填 0。

### 6.3 RSI 的隐藏填充问题

当前 `_compute_rsi()` 使用 `close.pct_change()`。在部分 pandas 版本中，默认 `fill_method` 会前向填充缺失价格，这会把缺失观测变成零收益。应显式使用 `pct_change(fill_method=None)`，并设置逐股最少有效观测数。现有测试没有覆盖“窗口中间存在缺价”的场景。

## 7. 横截面预处理五步精讲

设 `x_i,T` 是调仓日 T 股票 i 的原始因子。

### Step 1：金融行业适用性过滤

```text
若因子属于财务类 且 股票属于银行/非银金融：x_i,T = NaN
```

目的不是说金融股不能投资，而是普通工商企业财务比率不能直接套在金融资产负债表上。

### Step 2：MAD 去极值

当期横截面中位数：

```text
m_T = median_i(x_i,T)
MAD_T = median_i(|x_i,T − m_T|)
```

正态一致性尺度：

```text
sigma_robust ≈ 1.4826 × MAD_T
```

截断边界：

```text
[m_T − 3×1.4826×MAD_T, m_T + 3×1.4826×MAD_T]
```

超出边界的值被压到边界，不删除股票。边界只用 T 日横截面，绝不能拿 2012—2022 全样本中位数，否则 T 日使用了未来分布。

当前实现当 `MAD=0` 时退化为以中位数为中心的 `3×样本标准差` 边界；全部值相同时原样返回，随后标准化会变成全 `NaN`。这是合理的退化思路，但应在诊断中区分“因子无截面差异”和“数据失败”。

### Step 3：第一次 Z-score

```text
z_i,T = (x_i,T − mean_T(x)) / std_T(x)
```

只用非空股票估计均值和样本标准差，空值保持空。有效样本少于 2 或标准差近零时返回全 `NaN`。

第一次标准化对带截距的 OLS 残差方向和相对排序没有本质影响，主要是改善量纲和数值条件。真正必须保留的是中性化后的第二次标准化。

### Step 4：行业与规模中性化

横截面回归：

```text
z_i,T = α_T + Σ_k β_k,T × I(industry_i=k)
        + γ_T × log(free_float_mcap_i,T) + ε_i,T
```

最终保留残差 `ε_i,T`。其经济含义是：一只股票相对于同一行业、相近规模股票的“异常因子水平”。

为什么用自由流通市值：可交易部分决定指数增强的真实容量和规模暴露；总市值包含不可自由交易股份，会错估市场可交易规模。

为什么不能用全样本回归：因子中性化是每个 T 日独立的截面问题，回归系数也必须随市场结构变化。

当前实现的不足：

- 只要求总有效股票数不少于 30，没有检查回归参数数目、矩阵秩和条件数；
- 样本不足或 OLS 异常时返回原因子，属于“悄悄取消中性化”；
- 没有验证残差对每个行业 dummy 和 log 市值的暴露确实接近零；
- 2012—2013 的 `999999.SI` 会被当成合法行业类别。

### Step 5：残差再标准化

```text
factor_i,T = (ε_i,T − mean_T(ε)) / std_T(ε)
```

这样所有因子最终具有大致相同的横截面尺度，便于 IC 检验、等权或模型合成。注意 Z-score 只是统一尺度，不会自动把负向因子翻成正向。

### 7.1 因子方向在哪里处理

本阶段保存的是“原始经济定义方向”的标准化暴露，例如高 IVOL 仍然是较大的正数，但理论预期收益方向为负。

后续有三种处理方式：

- 单因子评价直接让 IC 的正负反映方向；
- IC_IR 加权时权重符号携带方向；
- 冷启动/等权回退使用 `FACTOR_DIRECTIONS`。

当前方向信息同时出现在因子 docstring、`src/signal/combiner.py` 的硬编码表和评价产物中，仍存在多来源漂移风险。业界更好的办法是让一次训练期评价生成带版本的因子元数据，生产合成只读取同一 run 锁定的方向，不对未知因子默认 `+1`。

## 8. 面板构建脚本应该如何理解

### 8.1 注册表现状

当前代码实际数量是：

| 集合 | 数量 |
|---|---:|
| 财务严格 PIT 因子 | 24 |
| 量价因子 | 20 |
| 另类因子 | 14 |
| 当前可由脚本注册构建 | 58 |
| 另有非默认 `dy_ttm` | 1 |
| 主目录历史 Parquet 文件 | 61 |
| 当前最终因子清单 | 18 |

脚本顶部“全部 36 个”、CLI 中“原有 27 个”、函数 docstring 中“15 个”等文字已经过期。运行时列表本身与三个 builder 注册表一致，因此主要是治理和面试误导问题，不是当前计算漏因子。

### 8.2 诊断字段

每个 `(T, factor)` 记录：

- `n_raw`：原始非空股票数；
- `n_fin_filtered`：金融股置空数；
- `n_winsor_clipped`：被截断的股票数；
- `n_neutralize_valid`：进入回归的股票数；
- `skipped_neutralize`：是否跳过中性化；
- `n_final`：最终非空股票数；
- `error_msg`：预处理异常。

这是很好的起点，但工业级还需要：覆盖率、数据年龄分位数、回归秩/条件数、最终行业和市值暴露、异常因子状态、输入数据版本和代码 commit。

### 8.3 失败传播为何是当前最严重的问题

三个 builder 对单因子异常都采用：

```python
except Exception:
    log.error(...)
    result[name] = all_nan_series
```

预处理异常也会写全 `NaN`。这能保证其他因子继续算完，但缺少最终质量门禁：脚本仍以退出码 0 结束。

之后 `_is_complete()` 只检查期望日期是否都在 index 中，不检查：

- 该期是否全 `NaN`；
- 是否有 `error_msg`；
- 覆盖率是否低于阈值；
- 中性化是否被跳过；
- 输入版本是否变化。

于是一次临时读取失败可能被写入正式面板，下一次 `--resume` 又会认为它完整。这是典型的 fail-open。

正确设计应是：

```text
单因子异常先隔离
→ 完成全批次
→ 统一质量门禁
→ 有错误/低覆盖/暴露超限则整体失败，不发布正式产物
→ 只有 PASS 产物原子移动到正式目录
```

### 8.4 `--resume` 的中间缺口问题

当前算法读取每个已有面板的 `index.max()`，从最早的最大日期之后统一追加。如果一个面板已经到 2022-12，但中间缺 2018-06，最大日期仍是 2022-12，因此不会重新计算 2018-06。

正确算法应为每个因子计算：

```text
missing_dates[factor] = expected_dates − existing_dates
```

循环日期时只为需要该日期的因子计算，或者按所有缺失日期的并集计算，不能用最大日期近似完整性。

### 8.5 训练与测试诊断没有真正隔离

测试模式把面板输出到 `factor_panels_test_run_N/`，但诊断仍使用模块常量：

```python
DIAGNOSTICS_PATH = data/processed/factor_panel_diagnostics.parquet
```

因此现有诊断文件覆盖 2012-01 到 2025-12，2023—2025 含 47 个因子，而正式训练/验证面板主目录只到 2022-12。这会污染训练期审计、误导覆盖率报告，也破坏一次 test run 的自包含性。

诊断路径必须由 `output_dir` 派生，并随 run 保存，不能写全局文件。

## 11. 业界级改造目标

### 11.1 建立机器可读的 FactorSpec

每个因子不只注册一个函数，还应注册元数据：

```python
@dataclass(frozen=True)
class FactorSpec:
    name: str
    category: str
    builder: Callable
    expected_direction: int | None
    pit_policy: str
    lookback: str
    min_observations: int
    financial_sector_policy: str
    missing_value_policy: str
    source_tables: tuple[str, ...]
    version: str
```

这样可以自动生成 CLI、教学因子卡、时间测试参数和 run manifest，避免数字、方向和适用范围散落。

### 11.2 因子面板发布采用两阶段提交

```text
临时目录计算
→ schema/日期/覆盖率/异常/中性化暴露检查
→ 生成 manifest + 校验和
→ 全部 PASS
→ 原子发布到正式目录
```

失败时保留临时诊断，但正式面板版本不变。

### 11.3 质量门禁建议

阈值不能凭经验直接硬编码，应先用训练期分布制定并写入 config。至少检查：

- 每期可投资域数量；
- `n_raw/n_universe` 和 `n_final/n_universe`；
- 相对历史覆盖率突降；
- `skipped_neutralize`；
- 截面标准差是否接近 1；
- 与 `log_free_float_mv` 的相关性；
- 每个行业的平均残差；
- 非有限值、重复日期/股票和列漂移；
- 输入文件指纹、代码 commit 和因子版本。

### 11.4 缺失值四分法

统一记录：

1. `not_applicable`：例如金融股的普通毛利率；
2. `not_yet_available`：财报尚未公告；
3. `no_event`：确认覆盖但无解禁/增减持；
4. `data_error`：应有数据但下载或处理失败。

这四类在统计处理上不应该全部变成一个 `NaN` 或一个 0。

### 11.5 中性化的可验收标准

每个 T、每个因子至少记录：

```text
n_obs
n_industries
design_rank
condition_number
corr(residual, log_mv)
max_abs_industry_mean_residual
```

任何中性化失败不应自动当成普通有效因子进入下游；可以返回状态 `FAILED_NEUTRALIZATION`，由策略明确决定跳过该因子或停止发布。

## 12. 面试高频问题与标准回答

### Q1：为什么因子处理必须按日做横截面，而不是全样本一起做？

因为调仓日只能知道当日横截面分布。用全样本均值、标准差或 MAD 会引入未来时期的信息，而且市场分布会随时间漂移。

### Q2：去极值、标准化、中性化的顺序是什么？

本项目是金融行业过滤 → MAD 去极值 → 初次 Z-score → 行业和 log 自由流通市值中性化 → 残差再 Z-score。核心原则是先控制极端值，再估计中性化回归，最后统一残差尺度。

### Q3：为什么用 MAD，不直接用均值加减三倍标准差？

均值和标准差会被极端值本身拉动；中位数和 MAD 对少量异常值更稳健。正态一致性系数 1.4826 把 MAD 转成近似标准差尺度。

### Q4：标准化会不会消除因子信息？

线性 Z-score 保留当期排序和相对距离，只改变位置和尺度。它不会自动修正方向，也不会解决异常值、行业偏离和未来函数。

### Q5：中性化到底做了什么？

对当期因子做 `factor ~ industry dummies + log(free_float_mcap)` 横截面回归，取残差，得到不能被行业和规模线性解释的个股部分。

### Q6：为什么不是总市值？

指数增强面对的是可交易股份，规模暴露应更接近自由流通市值；总市值会把限售或不可自由交易股份纳入规模度量。

### Q7：为什么财务因子排除金融股？

银行、保险、券商的资产负债表结构和收入定义与工商企业不同，普通杠杆、毛利率、现金流等指标不可直接比较。保守基线是置空，更精细方案是行业内专门建模。

### Q8：NaN 为什么不在因子层填 0？

NaN 可能代表不适用、未公告或数据错误。过早填 0 会把不同语义都变成“横截面中性”。单因子评价应 dropna；组合层若填 0，必须明确它代表不给 alpha，并保留覆盖率约束。

### Q9：TTM 如何构造？

最新累计值 + 上年年报值 − 上年同期累计值；所有报表版本必须在 T 日已经公告。存量指标如总资产通常取最新 PIT 快照，不做 TTM。

### Q10：为什么动量要跳过最近一个月？

减少短期反转、微观结构和近期冲击对中期动量的污染。`mom_6_1`、`mom_12_1` 表示回看约 6/12 月并跳过最近 1 月。

### Q11：为什么累计收益用端点价格比，不用逐日收益连乘？

端点比对中间缺行更鲁棒；逐日连乘若缺失会少乘若干天。但端点本身缺失时仍应返回 NaN，不能随意找未来最近价。

### Q12：停牌日收益应该是 0 还是 NaN？

经济意义上停牌期间价格不变可记 0，但数据缺失不能记 0。必须由交易状态识别停牌，不能看到 NaN 就一律填 0。

### Q13：怎样证明因子没有未来函数？

除了静态检查日期过滤，还要做未来注入不变性：给 T 之后追加极端数据，重新计算 `factor(T)`，结果必须逐值不变；财务因子再做公告日前后边界测试。

### Q14：因子 IC 很好是否说明因子有效？

不能。还要看 t 值、p 值、多重检验校正、分组单调性、验证期稳定性、换手和交易可实现性，并首先排查未来函数和样本选择偏差。

### Q15：为什么同一因子要保存原始值和处理后值？

原始值用于复核公式和数据问题，处理后值用于评价和合成。只保存最终 Z-score 会让异常来源、中性化影响和版本变化难以追踪。

### Q16：OLS 和 WLS 中性化怎么选？

OLS 让每只股票等权，适合截面选股基线；WLS 可让大市值股票更稳定或匹配风险模型口径。选择取决于目标，必须在训练/验证期比较暴露和稳健性，不能因为“业界常用”就直接替换。

### Q17：为什么因子数量越多不一定越好？

候选越多，多重比较和研究者自由度越大，容易从噪声中挑出偶然有效因子；高度相关因子还会让合成系数不稳定。应先有经济假设，再评价，并做 BH/Bonferroni 与样本外验证。

### Q18：本项目这一阶段最严重的工程问题是什么？

失败没有阻断正式发布：异常被写成全 NaN，而 resume 完整性只看日期。其次是测试面板隔离了，但诊断没有隔离，现有诊断已经混入测试期。

## 13. 一套可背诵的回答框架

面试官问“你怎么做因子数据处理”，按以下六句话回答：

1. **先定时点**：T 日盘后信号只使用 `available_at <= T` 的数据，交易在 T+1 开盘。
2. **再定股票池**：使用 T 日生效的指数成分并过滤新股、ST、停牌等状态。
3. **构造原始因子**：财务数据严格 PIT，流量指标做 TTM，行情使用后复权和真实交易日窗口。
4. **做截面预处理**：当日 MAD 去极值、Z-score、行业与 log 自由流通市值中性化、残差再标准化。
5. **保留缺失语义**：不把未公告、无事件、不适用和数据失败粗暴混成 0。
6. **质量门禁与验证**：检查覆盖率、暴露、时间不变性、版本和异常，合格后才发布面板。

简写记忆：

```text
时点 → 股票池 → 原始公式 → 截面处理 → 缺失语义 → 质量门禁
```

## 14. 建议的动手学习顺序

### 练习 1：手算一个财务因子

选一只股票和一个 T，列出 T 日可见的本期累计、上年年报、上年同期累计和 T 日总市值，手算 `ep_ttm`。

### 练习 2：手算一个量价窗口

从交易日历找到 T、T−20、T−120，核对 `mom_6_1` 的两个价格端点，确认使用后复权价。

### 练习 3：手算五只股票的预处理

给五个原始值、行业和自由流通市值，依次计算中位数、MAD、截断、Z-score、回归残差和第二次 Z-score。

### 练习 4：制造未来数据

给 T+1 之后的价格或公告值设置极端数，验证 `factor(T)` 不变。不要沿股票 index 做 shift。

### 练习 5：制造缺失语义

分别模拟停牌、无事件、接口漏数和未公告，检查代码是否能区分。当前代码会暴露出本文第 9 节的问题。

### 练习 6：检查一个真实面板

对每期计算覆盖率、均值、标准差、与 log 市值相关系数和行业均值，找出异常月份，再回到原始数据定位。
