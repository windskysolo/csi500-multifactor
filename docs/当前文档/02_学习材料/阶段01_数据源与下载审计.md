## 1. 先给结论

这套数据层已经具备一个认真量化项目的主要骨架：

- 股票代码统一采用带交易所后缀的 `ts_code`；
- 股票收益基于后复权价格计算；
- 基准强制使用中证500全收益指数；
- 财务记录保留 `pit_date` 与 `end_date`；
- PIT loader 只允许 `pit_date <= T` 且 `end_date < T`；
- 成分股、停牌、涨跌停、ST、新股被拆成显式状态；
- 大表使用 Parquet 和谓词下推；
- 核心边界已有较丰富的合成数据测试。

但目前还不能把数据层判定为业界级 PASS。最重要的阻塞项是：

1. **2012、2013 年行业未分类比例约为 31.8% 和 32.2%**，会直接影响训练期的行业中性化。
2. **ST 历史从 2020-12-15 才开始**，2012～2020 大部分训练期缺少可靠的 ST 标记。
3. `pledge_stat` 没有公告日期，代码直接用 `end_date <= T` 当作可用条件；这不是严格 PIT。
4. 原始下载的“文件存在即完成”逻辑不能区分合法空数据与 API 失败，且只向前补历史、不检查尾部是否完整。

因此，在这些问题解决并重新生成相关数据/因子面板之前，历史验证期 IR=2.150 只能称为“现有 run 的历史输出”，不能升级为经过本轮审计认证的结果。

## 4. 值得保留的正确设计

### 4.1 后复权收益口径正确

`process_daily_quote()`采用：

```python
close_adj = close * adj_factor
ret = close_adj.groupby(ts_code).pct_change()
```

它没有直接把原始 `pct_chg` 当作策略收益，这一点是正确的。除权除息发生时，未复权涨跌幅和后复权收益可能不同。

现有训练/验证范围检查结果：

- `(trade_date, ts_code)` 无重复；
- 复权因子空值率为 0；
- `ret` 空值主要来自每只股票的第一条记录；
- 股票代码均满足六位代码加交易所后缀。

### 4.2 自由流通市值计算可复现

代码明确使用：

```python
free_float_mv = free_share * close * 10_000
```

其中 `free_share` 为万股，最终市值单位为元。对现有数据复算的最大绝对差为 0。

这比直接使用 `circ_mv` 更符合项目约定的自由流通市值中性化口径。

### 4.3 全收益基准有强制检查

`process_index_quote()`要求原始指数代码只能为 `H00905.CSI`，并生成 `index_ret` 和 `nav`。训练/验证范围内：

- 指数日期无重复；
- 股票交易日与原始指数日期不存在缺口；
- 当前数据没有触发未来日期补值分支。

### 4.4 PIT loader 的基本方向正确

`pit_loader._filter_visible()`和`loader._pit_snapshot()`均要求：

```text
pit_date <= rebalance_date
end_date < rebalance_date
```

同一报告期的不同修订版本被保留到 loader 查询 T 日以后再选择，这比在转换阶段只留下最终版本更合理。

### 4.5 整行去重避免字段拼接

多个 loader 已从 `groupby.last()` 改为排序后 `drop_duplicates(..., keep="last")`，避免每列独立跳过 NaN 后把不同报告期的字段拼成一行。这是一个重要且正确的修复。

### 4.6 投资域和交易状态被区分

`TradeState`明确区分：

- `FREE`
- `LOCKED`
- `NO_BUY`
- `NO_SELL`
- `BUY_LIMIT`

这使“不能新买”和“已有持仓不能卖”不再被混成简单的 `tradable=False`。

## 6. 重大问题详解

### 6.1 D-001：行业历史覆盖不满足训练期要求

现有 `industry.parquet` 的未分类比例：

| 年份 | 未分类比例 |
|---|---:|
| 2011 | 30.90% |
| 2012 | 31.81% |
| 2013 | 32.23% |
| 2014 | 4.85% |
| 2015 | 0.94% |
| 2016 | 0.86% |
| 2020 | 2.73% |
| 2021 | 4.27% |
| 2022 | 5.30% |

当前转换脚本只要求全样本行业覆盖率大于 88%。全局均值能够通过，但它掩盖了训练早期两个年度约三分之一股票缺行业的事实。

这不是单纯的报告问题。中性化回归会把这些股票放入一个巨大的人造“未分类行业”，残差不再代表真实行业中性暴露。

更好的业界方案：

1. 使用带 `in_date`、`out_date` 的完整历史行业成员数据；
2. 对每个调仓截面单独设行业覆盖门槛，例如总体和单年/单月双重门槛；
3. 未分类股票超过阈值时阻断因子面板生成，而不是继续回归；
4. 对行业变更边界抽样核对生效日期；
5. 不能为了填满历史而用“当前行业”回填过去。

Tushare当前的分级行业成员接口明确提供纳入和剔除日期，因此应优先验证是否能通过该接口补齐历史，而不是接受静态快照式缺口。

### 6.2 D-002：训练期 ST 标记缺失

`namechange.csv`当前最早记录是 2020-12-11，最早 ST 记录是 2020-12-15。代码自己也记录了这一局限，但随后以“中证500通常会剔除ST”为理由继续运行。

这种解释不符合工业级验证标准：

- 指数剔除和股票被实施 ST 之间可能存在时间差；
- 无法证明所有训练期成分股从未处于特殊处理状态；
- 因子评价使用的可投资域可能因此污染。

正确处理应是补齐历史名称/ST状态；若数据源无法提供，应明确缩短样本期或把缺失状态纳入保守排除规则。改变训练起点属于研究决策，不能在代码中私自完成。

### 6.3 D-003、D-013、D-014：下载状态机不可靠

当前通用下载逻辑存在三个问题：

1. `_done()`只检查文件是否存在；
2. API连续失败后返回空 DataFrame，`_save()`仍写出空文件；
3. 已存在文件只检查是否缺少更早历史，不检查尾部是否达到目标结束日。

这意味着“API失败产生的空文件”和“股票确实没有该类数据”都会成为已完成状态。

本地已经发现：

```text
data/raw/margin/002085.SZ.csv：0字节
```

它可能是合法无数据，也可能是中断/失败；现有流程无法区分。

另外，`_save_merged()`在读取旧文件失败时会直接用新下载数据覆盖旧文件。这种降级不够安全，可能造成历史数据丢失。

业界方案应使用显式 manifest：

```text
dataset / key / requested_start / requested_end
API status / row_count / checksum / downloaded_at
empty_reason = legitimate_empty | api_failure | permission_denied
```

只有成功状态和覆盖区间都满足要求时，条目才算完成。旧文件读取失败时应停止并保留原文件，不能自动覆盖。

### 6.4 D-004：没有公告日的数据不能伪装成严格PIT

`pledge_stat`官方字段只有统计截止日 `end_date`，没有公告日。当前 loader 使用：

```python
end_date <= rebalance_date
```

截止日只说明数据统计到哪一天，不说明投资者何时能获得这份统计。如果T日直接使用截止到T的数据，就可能使用T日之后才发布的信息。

处理选择只能是以下之一：

- 找到有真实发布日期的数据源；
- 使用有依据、在训练前冻结的保守发布滞后；
- 仅作事后研究，不进入策略；
- 完全排除。

当前 `pledge_ratio`没有进入18因子主线，因此不需要因此推翻当前信号，但该接口必须保持隔离，不能直接晋升为候选因子。

同类原则也适用于只有统计期、调查日或事件日但没有实际公开时间的数据。

## 7. 其他重要改进

### 7.1 不要把裸 `assert` 当生产质量门禁

`csv_to_parquet.py`的许多验收条件使用：

```python
assert condition, "message"
```

Python使用优化模式 `python -O` 时会移除这些断言。生产数据契约应使用显式异常或独立验证器，例如：

```python
if not condition:
    raise DataContractError(message)
```

### 7.2 读取错误不能静默跳过

`_read_csv_safe()`对任意异常记录warning并返回None，`_load_csv_dir()`继续拼接剩余文件。这样可能产生部分数据集。

建议区分：

- 允许的空事件文件；
- 空文件但本应有行情的错误；
- schema错误；
- 编码错误；
- IO损坏；
- API权限错误。

核心行情、复权、daily basic和财务表应 fail closed；事件型数据可以允许显式的合法空文件。

### 7.3 全收益指数缺日不应默认使用未来记录回填

代码在指数缺少某个股票交易日时，用下一条记录的 `pre_close`重建缺失日 close。数学上它往往能恢复该收盘点位，但在T日视角属于从下一日记录倒推。

当前训练/验证数据不存在缺日，因此该分支没有影响现有数据。更稳健的方案是：

- 核心基准缺日直接阻断；或
- 使用另一份当日官方数据交叉补齐并记录来源；
- 若只为事后绩效重建，必须与信号数据隔离并显式标记。

### 7.4 SW2021不能自动降级到CITICS

`process_industry()`在SW2021文件不存在时会读取旧CITICS文件。即使打印warning，这也改变了模型含义，并违反项目统一行业口径。

正确行为是直接失败，除非用户明确批准一个新的实验口径。

### 7.5 行业名称编码损坏

现有 `industry_sw2021.csv` 和 `industry.parquet` 中31个行业名称均出现乱码，行业代码仍正常。

这不会直接破坏使用行业代码的中性化，但会污染：

- 行业归因报告；
- 图表标签；
- 人工检查；
- 结果解释。

应从可靠分类表按 `industry_code`重新映射中文名称，并增加编码/名称字典测试。

### 7.6 指数成员的“trade_date”需要业务验证

指数权重接口提供月度成分和一个 `trade_date`字段，但字段名本身不能证明它一定等于成分调整的正式生效日。项目硬规则要求按生效日对齐，因此需要抽取若干指数调整公告和实际生效日期做核对。

现有处理数据在2012～2022每月正好一个截面、每期500只、权重合计99.83～100.19，这说明结构完整，但不能替代生效日语义验证。

### 7.7 财务三表版本合并应改为事件驱动as-of模型

当前实现分别保留利润表、资产负债表、现金流量表的修订版本，再仅按 `(ts_code, end_date)`外连接。多个版本之间可能形成笛卡尔组合，最后按三表日期最大值生成宽表事件。

现有数据没有重复最终主键，最多每个报告期保留两个版本，但“无重复”并不能证明字段组合一定代表当时最新可见的三张表。

推荐结构：

1. 三张表分别保留原子版本历史；
2. 建立所有披露/修订事件时间线；
3. 在每个事件时点对三表分别做 backward as-of；
4. 组合出当时可见的宽表快照；
5. 用手工构造的交错修订案例测试。

## 8. 学习讲解：每个核心模块应如何理解

### 8.1 M1 日行情

需要掌握：

- 未复权、前复权、后复权的区别；
- 为什么收益必须由一致口径的价格序列计算；
- 停牌造成的日期缺口如何进入收益序列；
- 成交量为零时删除记录对因子窗口和回测的影响。

练习：选一只发生过分红送转的股票，用相邻两个交易日的 close和adj_factor手算后复权收益。

### 8.2 M2 每日基础指标

需要掌握：

- `total_mv`、`circ_mv`、自由流通市值的区别；
- 万股、万元、元之间的单位换算；
- 为什么中性化通常对市值取对数；
- 缺失自由流通股本为何不能简单填零。

练习：随机抽5条记录复算 `free_float_mv` 和 `log_free_float_mv`。

### 8.3 M3 全收益指数

需要掌握：

- 价格指数和全收益指数的差异；
- 为什么错误基准会系统性虚增超额收益；
- 指数收益、净值和超额收益之间的关系；
- 基准日历和股票日历如何对齐。

练习：用5个交易日的指数close手算 `index_ret` 和 `nav`。

### 8.4 M4 行业历史

需要掌握：

- 行业分类是随时间变化的数据，不是静态标签；
- `in_date <= T < out_date`的区间连接；
- 未分类股票对横截面回归的影响；
- 行业代码用于计算，行业名称用于解释。

练习：选一只历史上变更行业的股票，检查变更日前后两个截面的行业代码。

### 8.5 M5–M8 财务PIT

需要掌握：

- `end_date`回答“这是哪一期财报”；
- `ann_date/f_ann_date`回答“市场何时知道”；
- 财务修订为何必须保存多个版本；
- 存量指标和流量指标的区别；
- TTM如何由年报和季度累计值组合。

练习：对一只股票选定T日，列出T日前所有公告，然后手工决定最新可见报告和TTM。

### 8.6 M11 股票状态

需要掌握：

- ST/新股属于准入限制；
- 停牌属于持仓锁定；
- 涨停是不能增加，跌停是不能减少；
- 普通触板和一字封板的差异；
- 状态缺失应保守处理。

练习：构造一只同时ST和停牌的股票，验证状态优先级最终为 `LOCKED`。

### 8.7 M12 成分股快照

需要掌握：

- 指数成分股是随时间变化的；
- 公告日、调整日、生效日不同；
- 指数权重原始单位为百分数；
- 不可投资不等于已有持仓可以立即卖出。

练习：选连续两个月，比较新增、剔除股票及权重合计。

### 8.8 Loader与PIT工具

需要掌握：

- Parquet谓词下推；
- 全表缓存与范围读取的取舍；
- as-of查询；
- 同报告期修订版本选择；
- 陈旧财报过滤；
- TTM、同比和季度历史的不同用途。

练习：用同一只股票分别在公告日前一天、公告日和修订日后查询，比较返回快照。
