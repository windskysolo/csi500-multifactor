## 0. 先给结论

本项目的单因子评价主链已经具备一个合格研究框架的主要部件：

```text
T 日预处理因子
    ↓
T+1 开盘至下个调仓日后首个交易日开盘的 forward return
    ↓
训练期 Rank IC + IC_IR + t/p + BH 校正
    ↓
时间错位诊断 + 五分组 + 因子相关性去冗余 + IC decay
    ↓
训练期准入
    ↓
验证期只做稳定性报告，不回写 final_include
```

值得保留的设计包括：

- 使用截面 Spearman Rank IC，适合经过去极值和中性化后的选股排序信号；
- forward return 明确采用 `T+1 open_adj → T'+1 open_adj`，与策略实际成交假设一致；
- 用 `exit_date` 而不是因子日期切分训练/验证边界，避免标签跨样本期；
- 同时报告 IC 均值、IC_IR、t 值、p 值，并对批量检验做 BH 校正；
- 负向因子通过训练期 IC 符号统一方向，不会因为 `pct_positive` 较低而被误杀；
- 验证期稳定性没有直接写回准入结果，基本遵守了训练、验证、测试三者分工；
- `factor_summary.csv` 与 `final_factors.json` 的 18 个因子集合一致；
- 本次评价相关 75 项单元测试通过。

但是，按工业级“可复现准入”的门槛，本阶段当前结论是 **FAIL**。不是因为 IC 公式完全错误，而是准入证据链尚不够可靠：

1. 当前注册表已有 58 个因子，历史评价只覆盖 55 个；缺少 `asset_growth`、`share_issuance`、`mf_flow_ratio`，而评价脚本会扫描目录决定检验家族，候选集合没有被 manifest 锁定。
2. `final_factors.json` 的 `run_id="unset"`，且没有锁定因子面板、forward return、配置和代码输入哈希，不能证明当前 18 因子由当前定义重建。
3. 覆盖率以“全样本最大非空股票数”为分母：永久只有 200 只覆盖的因子也可能显示 100%，并且历史日期是否入样会依赖后续日期的最大覆盖。
4. 普通 t 检验把月度 IC 当成独立同分布；行业级实现应补 Newey–West/HAC 或 block bootstrap，并在多重检验前保留原始 p 值精度。
5. shift test 是泄露筛查启发式，不是未来函数的证明；当前 shift test 还没有沿用主 IC 的 50% 覆盖率门槛。
6. 因子相关性没有逐因子对检查共同有效股票数；IC decay 只看 lag1 与 lag3 是否同号，门槛过弱。
7. 五分组是无成本、等权的研究诊断，没有正式输出单调性、换手、容量和可交易性指标。
8. 健康监控的“12/24/36 月”实际取最后 12/24/36 个有效观测；稀疏因子可能跨越更长日历时间。
9. 验证报告中的 `1.96/sqrt(n)` 被称为 IC_IR 的 95% 置信区间，这是不严谨的近似，不能作为 IC_IR 置信区间解释。

因此，面试时最准确的表达是：

> 我实现了一套训练期驱动的单因子准入框架，包含 Rank IC、显著性和 FDR、分组收益、时序错位、衰减与相关性去冗余；验证期只作稳定性诊断。但历史 18 因子属于“当前主线正在使用的历史筛选清单”，还不能等同于“当前定义下已经工业级复验通过”，因为候选池版本、输入哈希、覆盖率口径和稳健标准误仍需闭环。

## 1. 这一阶段到底在回答什么

上一阶段把原始数据变成了调仓日 `T` 的横截面因子暴露。本阶段不是继续发明公式，而是回答四个问题：

1. **预测性**：因子排序与下一持有期股票收益排序是否相关？
2. **稳定性**：这种关系是否跨月份、子区间和验证期保持？
3. **可实现性**：头尾组收益是否拉开，方向、单调性和持有期是否合理？
4. **增量性**：因子是否只是另一个已选因子的重复表达？

这里必须区分三个对象：

| 对象 | 作用 | 能否进入信号 |
|---|---|---|
| `factor_T` | T 日盘后可见的截面暴露 | 可以 |
| `future_ret_T` | T+1 开盘到下一期退出开盘的评价标签 | 绝不可以反向进入因子 |
| `IC_T` | 当期截面因子与未来收益的相关系数 | 只能用于研究、历史训练或滚动权重 |

一句话记忆：

> 因子层生产解释变量，评价层生产未来标签并检验关系，信号层才决定如何组合；三个层次不能混写。

## 3. 时间轴：先把标签讲清楚

设：

- `T`：本月调仓日，盘后形成因子；
- `E(T)`：T 之后第一个实际交易日，即进场日；
- `T'`：下一调仓日；
- `X(T)`：T' 之后第一个实际交易日，即退出日。

代码定义：

```text
future_ret(T, i) = open_adj(X(T), i) / open_adj(E(T), i) - 1
```

例如：

```text
2020-11-30 盘后：生成 factor_T
2020-12-01 开盘：进入
2020-12-31 盘后：生成下一期目标
2021-01-04 开盘：退出本期、执行下一期
```

训练期截至 2020-12-31 时，不能仅凭 `T <= 2020-12-31` 把最后一个标签塞进训练集；必须要求退出日 `X(T) <= 2020-12-31`。项目用 `build_exit_date_map` 完成了这一点，这是正确且很重要的边界设计。

### 为什么 IC 可用原始收益，不一定要先减基准

在同一调仓日，基准收益是所有股票共同减去的常数：

```text
rank(stock_ret_i - benchmark_ret) = rank(stock_ret_i)
```

所以截面 Spearman IC 不变，Q5−Q1 中共同基准也会相消。正式组合绩效仍必须使用中证500全收益基准；这里只是说明单期截面排序检验为何可用原始个股收益。

### 当前缓存设计的优缺点

forward return 缓存会检查调仓日期哈希和 benchmark mode，缺 sidecar 会拒绝加载，这是优点。但它没有锁定 `daily_quote`、投资域和基准数据本身的内容哈希：底层数据修订后，日期没变的旧缓存仍可能被误用。

## 4. Rank IC：从一个截面到一条时间序列

### 4.1 单期 IC

调仓日 T 上有 N 只股票：

```text
IC_T = SpearmanCorr(rank(factor_T), rank(future_ret_T))
```

项目先取因子和收益都非空的股票交集，少于 10 只则返回 NaN。

为什么使用 Spearman：

- 只关心排序，不要求因子与收益呈线性关系；
- 对极端值比 Pearson 更稳健；
- 与截面选股“买高分、少配低分”的目标一致；
- 对单调变换不敏感，例如 `EP` 与 `rank(EP)` 排名一致。

它不能解决的问题：

- 不能证明因果关系；
- 不能自动排除行业、规模或流动性暴露；
- 不考虑交易成本和容量；
- 对大量并列值、覆盖率变化和样本选择仍敏感。

### 4.2 多期 IC 时序

对每个月独立计算 `IC_T`，形成：

```text
IC_1, IC_2, ..., IC_n
```

样本单位是“月份”，不是股票。一个月 500 只股票只是用于估计一个截面 IC；统计显著性的时间样本量在当前训练期大多是 106，而不是 `106 × 500`。

这是面试高频陷阱：把所有股票月份堆在一起计算一个相关系数，会忽略截面结构、时期权重和标准误聚类问题。

### 4.3 当前覆盖率缺陷

项目定义：

```text
coverage_T = 当期因子非空数 / 该因子全样本最大非空数
```

它解决了“所有历史股票列并集远大于当期500只”的问题，却不是严格的投资域覆盖率。工业级定义应是：

```text
coverage_T = 有效因子且有可用标签的股票数 / 当期合格可投资域股票数
```

当前实现有两个偏差：

- 永久只覆盖 200 只股票的因子，只要每期都覆盖这 200 只，仍可接近 100%；
- 分母使用全样本最大值，早期日期是否通过门槛受未来样本覆盖情况影响。

修复时应把 `eligible_codes_by_date` 显式传入评价器，并同时报告 numerator、denominator、覆盖股票特征和行业分布。

## 5. IC 均值、IC_IR、t 值、p 值分别回答什么

设月度 IC 均值和样本标准差为：

```text
mean_IC = mean(IC_T)
std_IC  = std(IC_T, ddof=1)
IC_IR   = mean_IC / std_IC
t       = mean_IC / (std_IC / sqrt(n))
```

| 指标 | 回答的问题 | 不能回答的问题 |
|---|---|---|
| IC 均值 | 平均方向和平均截面预测强度 | 是否稳定、是否显著 |
| IC 标准差 | 每月 IC 波动多大 | 平均预测是否为零 |
| IC_IR | 单位 IC 波动对应多少平均 IC | 交易后的组合 IR |
| t 值 / p 值 | 在统计假设下，均值为零是否难以解释数据 | 经济价值、因果、样本外稳定性 |
| 正向月份占比 | 方向命中频率 | 收益幅度和尾部风险 |

### IC_IR 不是组合 IR

项目里的 IC_IR 没有乘 `sqrt(12)`，是月度 IC 均值除月度 IC 标准差。组合 IR 则是超额收益均值除 tracking error，通常年化。两者名字相似，但变量、风险和单位完全不同。

### 当前 t 检验为什么还不够

普通 t 检验假设月度 IC 近似独立同分布。实际中因子暴露、市场风格和股票池都有持续性，IC 可能自相关、异方差。改进顺序：

1. 继续报告普通 t 值，便于与历史结果对比；
2. 增加 Newey–West/HAC t 值，lag 事前固定；
3. 用按月份的 block bootstrap 给均值和 IC_IR 置信区间；
4. 同时展示年度/市场状态分段，不只看总体显著性。

当前 `ic_summary` 先把 p 值四舍五入到 6 位，再交给 BH。很小的 p 值会变成 0，排序和精度被破坏。正确做法是内部保留全精度，只在 CSV/Markdown 展示层格式化。

## 6. 多重检验：为什么不能看 55 个原始 p 值

若每个因子都以 5% 显著性检验，测试 55 个纯噪声因子，至少出现一个假阳性的概率约为：

```text
1 - (1 - 0.05)^55 ≈ 94%
```

因此批量筛因子必须校正。

### Bonferroni 与 BH

| 方法 | 控制目标 | 特点 | 更适合 |
|---|---|---|---|
| Bonferroni | FWER：至少一个假阳性的概率 | 很保守 | 少量关键假设、确认性研究 |
| BH | FDR：被判显著结果中的期望假发现比例 | 更有检验力 | 有明确候选池的探索性因子筛选 |

项目使用 BH 是合理选择，但前提是“检验家族”必须事前确定并锁定。当前通过目录扫描加载因子，新增或残留 Parquet 会改变 BH 家族和最终清单；这是为什么候选 manifest 不只是工程洁癖，而是统计口径的一部分。

相关因子会使 BH 的解释更复杂，但并不意味着可以不校正。工业级还应记录：候选提出日期、经济假设、公式版本、是否复用同一数据挖掘，以及一共尝试过多少版本，防止只对幸存版本做 FDR。

## 7. 本项目五道准入门

历史评价流程的 `final_include` 由训练期信息决定：

### Gate 1：IC 有效性

同时满足：

```text
abs(IC_IR)   >= 0.30
abs(IC_mean) >= 0.02
BH p-value   <  0.05
方向一致月份占比 >= 0.55
```

这是统计和最低经济强度门槛。阈值必须在配置和研究协议中冻结，不能看完结果再调。

### Gate 2：时间错位筛查

拒绝条件：

- `lead_ratio >= 2.0`；或
- 上一期因子预测本期标签反而明显强于原始对齐，诊断为 `reverse`。

`1.5 <= lead_ratio < 2.0` 仅标记 `lead_warn`，不自动排除。

### Gate 3：高相关去冗余

先按 `abs(IC_IR)` 降序，若候选与任一已选因子的平均截面 Spearman `|r| > 0.70`，保留较强者。

历史上被这道门去掉的 6 个因子：

| 被去掉 | 保留 | 平均绝对相关系数 |
|---|---|---:|
| `vol_60d` | `ivol_60d` | 0.893 |
| `np_yoy` | `roe_delta` | 0.796 |
| `garp` | `ep_ttm` | 0.849 |
| `roa` | `q_roe` | 0.800 |
| `roe` | `q_roe` | 0.879 |
| `roe_smoothed_4q` | `q_roe` | 0.736 |

注意：贪心去冗余是顺序依赖算法，不过当前先按 IC_IR 排序且文件名排序加载，因此同一输入下可重复。更严谨的方案是锁定候选顺序并用相关聚类/图分组，在每个经济主题内选择代表因子，同时检查增量 IC 和组合边际贡献。

### Gate 4：方向化五分组 Sharpe

先由训练期 IC 符号确定方向：

```text
direction = sign(mean_IC_train)
DirectionalLS = direction × (Q5 - Q1)
```

要求：

```text
abs(DirectionalLS Sharpe) >= 0.5
```

因为方向和 Sharpe 都在同一训练集估计，这只是训练期准入门，不是独立样本外证明。

### Gate 5：IC decay

当前规则只要求：

```text
IC_IR_lag1 × IC_IR_lag3 > 0
```

即第三个月仍同向。它没有要求 lag3 足够大、显著或平滑衰减，所以“lag3=0.001 但同号”也能通过。更稳健的门槛应结合：最小绝对 IC、置信区间、相对衰减比例和组合实际持有期，而不是只看符号。

## 8. 五分组回测怎样正确阅读

每个调仓日把有效股票按因子值等频分为 Q1 至 Q5，各组等权：

```text
Qk_ret(T) = mean(future_ret_i | i in Qk)
LS(T)     = Q5_ret(T) - Q1_ret(T)
```

应检查四件事：

1. **方向**：正向因子是否 Q5 高于 Q1；负向因子反之。
2. **单调性**：Q1→Q5 是否大致阶梯变化，而非只有某一组异常。
3. **稳定性**：年度、牛熊和高低波动阶段是否一致。
4. **可实现性**：头尾组换手、停牌、涨跌停、流动性和容量是否可接受。

当前代码做到了等频分组、每组最少 5 只、重复值导致不足 5 组时整期跳过，并把原始 Q5−Q1 与方向化多空分开，这是正确的。

当前局限：

- 不含成本，不能当作可交易策略收益；
- 等权，不匹配中证500增强组合的基准权重和约束；
- 年化收益使用 `mean × 12`，只是算术近似；
- 没有直接输出单调性分数、组内股票数、换手和容量；
- 分组前有效因子集合与有收益标签集合的选择可能带来样本差异，需要披露。

面试回答：

> 五分组用于检查排序的经济形态，IC用于衡量连续排序关系，二者互补。只有头尾收益而中间组不单调，可能是极端值、非线性或小样本，并不能说明因子可稳定交易。

## 9. shift test：能发现什么，不能证明什么

项目计算：

```text
original: factor(T)   vs future_ret(T)
lag_1:   factor(T-1) vs future_ret(T)
lag_2:   factor(T-2) vs future_ret(T)
lead_1:  factor(T+1) vs future_ret(T)
```

直觉：如果 `factor(T+1)` 异常擅长解释 `future_ret(T)`，可能是因子文件时间戳、财务公告日或标签对齐错误。

但它只能发出嫌疑，不能作定罪或无罪证明：

- 价值、质量等高持久性因子，lag/lead 都可能较强；
- 收益自相关和市场状态延续也会产生 lead 相关；
- 泄露若只影响少数股票或月份，不一定让 lead ratio 超过 2；
- 一个完全错误但稳定的因子也可能通过 shift test。

真正的未来函数防线应是：

1. **来源级 PIT 测试**：公告时间、生效日和修订版本；
2. **未来注入不变性**：任意修改 T 之后原始数据，`factor(T)` 必须不变；
3. **标签隔离**：因子模块不能依赖 future return 文件；
4. **边界 golden case**：手算 T、T+1、T'、T'+1；
5. **shift test**：作为最后的统计异常探针。

当前 `batch_shift_test` 没有传入主 IC 使用的 50% 覆盖率阈值，因此 Gate 1 与 Gate 2 可能基于不同月份样本。这应统一。

- 检查 IC 衰减、覆盖率和市场状态稳定性；
- 比较已经事前定义的候选方案。

不应在看到验证结果后反复改因子再把同一验证期称为样本外。项目当前 `valid_stability` 只写报告、不直接控制 `final_include`，这是纪律上的优点。但如果后来根据验证期反复改公式，验证期事实上已经变成第二训练集，必须记录研究轮次并再安排新的未触碰 holdout 或嵌套 walk-forward。

### 测试期 2023—2025

只用于项目末期一次性或受控最终评价，不能用于选因子、改方向、调阈值。当前测试集台账显示已使用 1 次、剩余 2 次；本次没有运行或读取新的测试结果。

### 当前验证期稳定性现状

- stable：8 个；

## 13. 五个最适合做因子工程迭代的案例

因子工程不是“换几十个参数找最高 IC”，而是：提出可证伪假设，定位数据或经济机制，做一个最小改动，使用冻结评价协议比较，并保留失败版本。

### 案例一：`high_52w → high_52w_v2`——时间标签变化会改变问题定义

原版：

```text
high_52w = close_adj(T) / max(high_adj, 历史窗口)
```

v2：

```text
high_52w_v2 = close_adj(T-20td) / max(high_adj, T-271td:T-20td)
```

历史结果：原版 IC_IR=0.054、lead ratio=37.6；v2 IC_IR=0.328、lead ratio=0.092，并进入清单。

这个案例适合讲“时间错位发现问题 → 修改端点 → 重新评价”，但当前代码注释称原版与 `close(T+1)/close(T)` 共享分母，而当前标签实际是 `open_adj(T+1) → open_adj(T'+1)`。也就是说，旧注释对应过往标签口径，不能原样解释当前机制。

改进实验：

1. 锁定当前 open-to-open 标签；
2. 对比原版、仅跳过 5/10/20 日、传统 52 周高点距离；
3. 每个版本先做未来注入不变性，再做 IC/分组；
4. 参数只能在训练内选，验证期一次确认；
5. 记录高点窗口变化带来的换手和与动量因子的相关性。

面试亮点：**因子定义必须和标签合同一起版本化；旧结论不能脱离当时的标签继续引用。**

### 案例二：`ivol_60d`——把缺失填 0 的性能捷径改成统计语义正确

当前 CAPM：

```text
r_i,t = alpha_i + beta_i r_m,t + epsilon_i,t
ivol_i = std(epsilon_i,t)
```

为了向量化，代码把股票缺失日收益填成 0，再统一 OLS，最后只按有效天数门槛过滤。这会把“数据缺失”或“停牌”当成真实零收益，可能压低波动并改变 beta。

改进版本：

- 每只股票只在股票与市场收益共同非空的日期回归；
- 明确停牌日是应保留零收益、剔除，还是使用价格不变但不可交易标记；
- 设置最小有效天数和最大连续缺失天数；
- 对比 CAPM、行业调整和更完整风险模型残差，但每次只改变一个维度；
- 输出每股 `n_obs`、beta、残差自由度和覆盖率。

评价重点不只看 IC 是否更高，还看缺失敏感性、行业暴露、换手、极端月份和验证期稳定性。

### 案例三：`rev_acceleration`——PIT 合法不等于季度序列正确

公式需要 `q0, q1, q4, q5`：

```text
yoy_now  = (q0 - q4) / abs(q4)
yoy_prev = (q1 - q5) / abs(q5)
accel    = yoy_now - yoy_prev
```

当前 `get_quarterly_history` 按可见记录排序取最近季度，但没有验证报告期连续性。若缺季，`q1` 可能不是前一季度，因子仍会给出看似正常的数。

改进版本：

- 从 `end_date` 显式推导期待的 6 个报告期；
- 缺任一期则 NaN，不把非相邻报告硬凑；
- 区分累计财务字段和单季字段，先正确转单季再同比；
- 设置公告陈旧度并记录重述版本；
- 对极小去年基数做有经济含义的稳健处理，不能只靠横截面 winsorize 掩盖。

这是很好的面试案例：**最危险的财务 bug 往往不是公式，而是季度身份、累计/单季口径和公告可见时间。**

### 案例四：`analyst_eps_revision`——必须固定预测口径和分析师去重

当前定义比较两个时间窗口中 EPS 预测中位数：

```text
median(recent EPS) / median(prior EPS) - 1
```

但若不固定预测年度/滚动十二月口径，近期报告可能更多预测下一财年、远期报告预测本财年，得到的“上调”其实是 horizon rollover。多家报告也可能来自同一机构重复更新，造成机构权重不均。

改进版本：

- 固定 `forecast_year`，或构造 FY1/FY2 到固定目标日的插值；
- 每个机构在每个窗口只保留 PIT 最新一条，再做跨机构中位数；
- 分开“老分析师上调”和“新覆盖进入”效应；
- 报告机构数、预测离散度和预测年龄；
- 用绝对修正、相对修正、价格归一化修正做事前定义的少量比较。

### 案例五：`piotroski_f`——高训练效果、验证反转时怎样研究

当前是 7 个二元财务分项，至少 5 项有效才计分。训练 IC_IR=0.615、方向化 Sharpe=1.889，但验证状态是 reverse；后续消融又将它列为移除候选。

不能做的事：看到验证反转后拆分到找到一个验证期最好版本，再称其样本外有效。

正确路径：

1. 冻结“为什么反转”的假设：行业构成、早期伪行业、中小盘壳价值、分项缺失、会计制度或疫情状态；
2. 在训练期内部按年份、行业和市值分组做 component attribution；
3. 比较每个 F 分项的覆盖、边际 IC 和相关性；
4. 检查 0—7 离散分值造成的 ties，以及至少 5 项有效是否让不同股票分数不可比；
5. 预注册“完整案例删除”“分项归一后合成”或“行业内计分”等少量 challenger；
6. 使用新的严格滚动/保留样本确认，不回头消耗测试集。

这个案例最能展示研究纪律：**异常结果首先触发诊断和预注册实验，而不是即时调参。**

### 可选第六案例：`hk_hold_ratio / hk_hold_chg`

北向持仓数据在 2024-08 后披露频率变化，当前代码已做季度 PIT offset 和 staleness 处理。但历史评价结束于 2022，无法验证新制度定义；而清单生成时间又早于后续季度版修订。应将“因子名相同但数据语义变更”视为新版本，重新跑训练/验证评价并锁定输入，而不是沿用旧 IC 数字。

## 14. 工业级因子工程实验模板

每次改进只按以下模板走：

```text
研究问题
  ↓
经济机制与失败机制
  ↓
因子卡：公式、字段、PIT、适用股票、缺失、方向、窗口
  ↓
冻结候选版本与评价协议
  ↓
公式 golden case + 未来注入不变性 + 覆盖率测试
  ↓
训练期 IC/HAC t/BH/分组/相关性/衰减/换手
  ↓
训练内 walk-forward 或子区间稳定性
  ↓
验证期一次确认
  ↓
保存成功和失败版本、输入哈希、代码提交、结论
```

建议每个 challenger 表至少包含：

| 字段 | 内容 |
|---|---|
| `experiment_id` | 唯一且不可覆盖 |
| hypothesis | 为什么改、预期改善什么失败模式 |
| base_factor | 基于哪个冻结版本 |
| formula_version | 公式和窗口 |
| data_version | 原始/处理数据 manifest |
| candidate_family | 同时被检验的完整候选集合 |
| label_contract | T+1 open 到 T'+1 open |
| train/valid scope | 明确日期和 exit-date 边界 |
| gates | 事前阈值 |
| results | IC、HAC t、BH、分组、覆盖、相关、换手 |
| decision | keep / reject / diagnose |
| limitations | 未解决问题 |

13. 训练内选方向、看五分组 Sharpe、过五道门后报告同期指标，存在选择乐观偏差；后续模型评估应做嵌套/滚动选择。

### P2：研究解释和工程完善

14. 五分组缺正式单调性、组内样本、换手、容量和成本敏感性。  
15. 部分阈值存在模块级常量，应纳入集中配置与 run snapshot。

```text
输入 manifest/不可变 run
→ 当期投资域覆盖率
→ 全精度 p + HAC/bootstrap
→ 统一 shift 样本并降级为诊断
→ pairwise overlap + 更强 decay
→ 分组可实现性
→ 健康窗口与报告文字
```

## 16. 面试高频问答

### Q1：什么是 IC？

IC 是某个调仓日横截面上因子值与下一持有期收益的相关系数。本项目用 Spearman，所以衡量排序关系。每月得到一个 IC，再在时间上研究均值、波动和显著性。

### Q2：为什么不用把所有股票月份堆起来算相关？

因为选股是逐期截面决策，股票池和市场状态随时间变化。堆叠会让股票数多的时期权重更大，还忽略同月股票相关和跨月序列相关。

### Q3：Spearman 和 Pearson 怎么选？

Spearman 适合排序型、非线性但单调的因子，对极端值更稳健；Pearson 衡量线性关系并保留距离信息。可以并报作敏感性分析，但主口径必须事前固定。

### Q4：IC_IR 高说明什么？

说明平均 IC 相对于月度 IC 波动较高，即预测关系更稳定。它不是组合收益 IR，也不能直接转换为可实现收益。

### Q5：IC 均值很小但显著，能用吗？

不一定。大样本可让很小效应显著，所以要同时看最低经济强度、分组价差、换手、容量、成本和增量贡献。本项目因此同时要求 `|IC mean|>=0.02`。

### Q6：为什么要 BH？

因为同时测试几十个因子会大幅增加假阳性。BH 控制显著结果中的期望假发现比例，比 Bonferroni 更适合有事前候选池的探索筛选。

### Q7：BH 后显著就证明因子有效吗？

不是。它只在给定检验家族、统计假设和样本下控制错误发现；不能解决数据挖掘未登记、未来函数、错误 PIT、经济不可交易或样本外失效。

### Q8：为什么前向收益从 T+1 开盘开始？

因为 T 日盘后才形成信号，T 日收盘成交会引入不可实现假设。退出也在下一调仓日后的首个交易日开盘，确保评价标签与回测成交一致。

### Q9：为什么按 exit date 切分？

若只按因子日期切分，训练期最后一期收益可能跨入验证期。按退出日要求整个标签都落在该样本区间内，才能避免边界泄露。

### Q10：五分组看什么？

看方向、单调性、头尾差和稳定性。它是经济形态诊断，不含成本时不能当成正式策略回测。

### Q11：负 IC 是坏因子吗？

不是。稳定负 IC 表示反向使用即可。需要担心的是方向随时期翻转、负向机制无法解释，或只有数据错误导致的负相关。

### Q12：shift test 能证明没有未来函数吗？

不能。它是异常探针，会受因子持久性和收益自相关影响。无未来函数要靠 PIT、未来数据注入不变性、依赖隔离和手工时间边界共同证明。

### Q13：为什么高相关因子要去冗余？

它们重复表达同一风险或收益来源，会重复计权并使模型系数不稳定。但不能只看一张总体相关矩阵，还要看经济主题、状态相关和加入组合后的边际贡献。

### Q14：验证期方向翻转怎么办？

先检查数据和定义，再提出可证伪原因，在训练内部或新的滚动框架验证。不要直接根据验证期反复改公式，否则验证集变成训练集。

### Q15：为什么 `piotroski_f` 验证反转还在 18 因子里？

因为历史准入只由训练期门控制，验证状态不回流。它现在是移除候选而非已移除；后续需预注册消融或改进实验再决定。

### Q16：覆盖率只报平均值够吗？

不够。还要看每期分母、行业和市值分布、数据起始日、缺失机制以及有标签交集。稳定覆盖 200 只并不等于覆盖了 500 只投资域。

### Q17：普通 t 值有什么问题？

月度 IC 可能自相关和异方差，iid 标准误会偏乐观。应补 Newey–West/HAC 或按时间 block bootstrap。

### Q18：怎样判断一个因子有增量价值？

先看与已有因子相关，再做正交化/条件 IC、加入现有信号后的边际 IC、系数稳定性和组合层消融；不能只看单因子 IC 排名。

### Q19：为何不直接选 IC_IR 最高的 18 个？

因为还要防显著性假阳性、时间错位、因子冗余、非单调和信号寿命问题。单一指标排序容易选出重复或不可实现因子。

### Q20：你会怎样把本项目提升到业界级？

先锁定候选、数据、标签和代码版本，再修正当期覆盖率；内部保留全精度并报告 HAC/bootstrap；把 shift 降级为辅助诊断、补来源级 PIT 与未来注入测试；加入 pairwise overlap、单调性、换手容量和嵌套滚动评价；最后在不可变 run 中生成准入清单。

### Q21：因子效果衰减时，是改公式还是删因子？

先判断是数据质量、制度变化、拥挤、风险暴露还是随机波动。只有事前假设和新的非污染样本支持时才改；否则降权、观察或删除都应作为预注册决策，不追着最近表现调参。

### Q22：因子挖掘最常见的过拟合来源是什么？

大量未登记版本、反复查看验证/测试、参数网格过大、幸存者偏差、错误 PIT、只报最佳区间、同一数据既定方向又报表现，以及忽略交易成本。

## 17. 一套可背诵的回答框架

面试官问“你怎样做单因子检验”，用下面八句话：

1. **先冻结合同**：因子在 T 日盘后生成，标签是 T+1 开盘到下一调仓执行日开盘。
2. **严格切样本**：按标签退出日切训练、验证、测试，避免收益跨边界。
3. **算截面 Rank IC**：每月在当期合格投资域和非空交集上计算 Spearman IC。
4. **看强度和稳定性**：同时报告 IC 均值、IC_IR、HAC t/p、方向月份占比和覆盖率。
5. **控制多重检验**：对事前锁定候选池做 BH 或更保守校正。
6. **看经济形态**：五分组检查方向、单调性和头尾差，同时披露换手、容量和成本敏感性。
7. **做风险诊断**：PIT/未来注入是主防线，shift、decay、子区间和相关性是辅助门。
8. **遵守样本纪律**：训练期准入，验证期确认，测试期只做最终评价；全部输入和结论落入不可变 run。

简写：

```text
标签合同 → exit-date 切分 → Rank IC → 稳健显著性 → FDR
→ 分组实现性 → 泄露/衰减/冗余 → 三段样本纪律与版本锁
```

## 18. 建议动手练习

### 练习 1：手算一个月的 Rank IC

取 10 只股票，分别给因子和未来收益排名，计算排名差和 Spearman；加入极端收益，观察 Rank IC 与 Pearson 的差异。

### 练习 2：画清时间轴

任选连续两个调仓日，从交易日历找 T+1 与 T'+1，手算一只股票的 `open_adj` forward return，并判断它属于训练还是验证。

### 练习 3：制造四类合成因子

构造：稳定正向、纯噪声、稳定负向、直接含未来收益的泄露因子，验证 IC、方向、BH、五分组和 shift 能否给出预期结果。再构造高持久性但无泄露因子，观察 shift 的误报可能。

### 练习 4：重算覆盖率

用同一因子分别计算“相对全样本最大覆盖”和“相对当期投资域覆盖”，找出结论不同的月份。

### 练习 5：比较普通 t 与 HAC t

对一条有正自相关的合成 IC 序列计算两种标准误，理解为什么普通 t 值可能过于乐观。

### 练习 6：拆解一个排除因子

选 `vol_60d`：确认它 Gate 1 有效，但因与 `ivol_60d` 相关 0.893 被去冗余。回答“统计有效”和“应进入多因子池”为何不是同一个问题。

### 练习 7：完成一个因子工程案例

优先从 `ivol_60d` 或 `rev_acceleration` 选一个，先写失败测试和实验卡，再实现 challenger；不得覆盖当前因子文件或读取测试期结果。
