# 中证500多因子增强策略：阶段改进计划（修订版）

> 本文档整合因子体系、评价方法、组合优化三个层面的所有改进方向。
>
> **执行原则**：先确认基线正确，再做可控的单变量实验，保证每一步 IR 变化都可归因。
>
> 相关子文档：
> - `improve/optimizer_diagnosis.md` — 优化器深度诊断
> - `factor_evaluation_improvement_plan.md` — 因子评价体系修改方案
> - `factor_engineering_plan.md` — 新因子构建方案

---

> **研究前提：冻结基线**
>
> 所有阶段的 IR 改善，都以 **`frozen_baseline_icir_topn50_ew`**（ICIR加权 + Top50排序种子 + L3约束感知等权，无 QP）作为参照下限（验证期 IR=0.924）。  
> 冻结基线永不改变。若某个改进方向的最终 IR 低于冻结基线，说明引入的复杂度没有带来实质收益。

## 执行路线图总览

```
阶段 0  【立即】   基线一致性冻结（口径确认，产物对齐）
阶段 1  【随后】   优化器 P0：约束参数网格实验（对照，不直接替换）
阶段 2  【随后】   优化器 P1：换手惩罚（训练期校准，验证期单次对照）
阶段 3  【中期】   因子评价体系修正（lead_ratio 分级、IC decay 等）
阶段 4  【中期】   低风险因子扩展（现有因子改进与变体）
阶段 5  【中期】   新因子工程（动量变体、Piotroski、GARP）
阶段 6  【后期】   信号合成升级（alpha 量纲转换 + Ridge 回归）
阶段 7  【最终】   测试集门禁确认，决定是否进入测试集
```

**为什么这个顺序**：优化器参数调整会改变 IR，基线不稳时无法判断 IR 变化来自约束变化、旧产物、因子口径还是信号本身。必须先冻结基线，再做单变量实验。

## 阶段 0：基线一致性冻结（立即执行）

**目标**：确认当前产物口径全部正确，建立可信的基线 IR，后续一切改动都以此为对照。

### 0.1 确认训练/验证集划分

```
训练期：2012-01-01 至 2020-12-31（当前分支 feature/expand-train-2012 目标）
验证期：2021-01-01 至 2022-12-31（赛道牛+极端熊，代表性强）
测试期：2023-01-01 至 2025-12-31（剩余 ≤ 2 次机会）
```

确认 `config.py` 中时间切分参数与上述一致。

### 0.2 确认 39 因子口径与元数据

- 因子池完整列表与 `config.py` 中的 `CANDIDATE_FACTORS` 一致
- 每个因子的方向标记（正向/负向）正确
- 排除列表（ST、新股、停牌）逻辑未变动
- 中性化基准：申万一级（SW2021，31 个行业）+ log(自由流通市值)

### 0.3 验证 PIT 处理严格性

这是最隐蔽的错误，一旦混入未来函数，训练期 IC 会虚高，测试期必然崩塌，且回测阶段无法发现。

- 所有财务因子只使用 `ann_date`（公告日）早于 T 日的数据，不使用 `end_date`（报告期）
- 对每个财务因子抽查 5-10 只股票，手动核对可用日期
- 运行 **Shift Test**：所有因子整体后移一期，IC_IR 应剧烈下降（降幅 > 50%）；否则存在未来函数

### 0.4 确认基准使用全收益指数

- 必须使用中证 500 **全收益指数**（含分红再投资），不是价格指数
- 价格指数每年少计算约 2-3% 的股息收益，超额收益被虚增
- 检查 `config.py` 中基准代码是否为全收益版本

### 0.5 记录当前基线 IR

跑出训练期 2012-2020 完整 IC 统计和回测 IR，明确记录：
- 每个因子的 IC_IR、通过/拒绝状态
- 组合优化后的年化超额、跟踪误差、最大超额回撤
- fallback 分布（L1/L2/L3 各占多少期）
- 年化双边换手率

**这一步的意义**：如果训练期 IR 已经健康（> 0.5），当前验证期问题主要是 2022 年极端行情导致的，不需要大规模改动。只有训练期 IR 也偏低，才说明因子体系有根本性问题。

## 阶段 1：优化器 P0——约束参数网格实验

> 依据：`improve/optimizer_diagnosis.md` 问题 1

### 核心问题：TE 约束从未 binding

**推导**：中证 500 约 500 只股票，单股偏离 ±1%，在零相关假设下组合最大年化 TE 约 3.5%，考虑 A 股正相关（约 0.3）后实际上限约 2.5-3%。TE 目标 5% 物理上无法达到，约束永远满足但永远不紧（slack），优化器实际等价于 L2 线性规划，信号无法转化为有效权重偏离。

**注意**：这不是说 L1 会频繁失败——恰恰相反，L1 因为 TE 约束极松，几乎一直成功。问题是成功了但约束没在发力。

### 实验设计（预声明三组对照，不直接替换正式参数）

| 配置 | TE 目标 | 单股偏离 | 行业偏离 | 说明 |
|------|--------|--------|--------|------|
| O0（当前基线） | 5% | ±1% | ±2% | 不变，作为对照 |
| O1（温和放宽） | 6% | ±1.5% | ±3% | 中间档 |
| O2（业界参考） | 8% | ±2% | ±4% | 国内量化增强主流 |

**三组配置在训练期分别跑一遍，对比以下指标**（不是只看 IR）：

- **Realized TE**：实际跟踪误差是否从 ~2-3% 向目标靠拢
- **TE constraint binding 比例**：每期优化是否有 TE 约束真正 active
- **单股/行业偏离分布**：是否充分利用了放宽的空间
- **Fallback 分布**：训练期早期（成分股池小）L3 是否减少
- **IR、超额收益、超额最大回撤**

**只有在训练期表现稳定、各指标逻辑自洽后**，才将选定配置写入正式 `config.py`。

## 阶段 2：优化器 P1——换手成本惩罚

> 依据：`improve/optimizer_diagnosis.md` 问题 3

### 核心问题：成本侵蚀超额

当前年化双边换手约 745%（7.45 倍），**在项目目标 5-15 倍以内，不违规**。加换手惩罚的理由是成本侵蚀：

```
745% × (2.5 bps 佣金 + 2.5 bps 佣金 + 8 bps 印花税) × 双边 ≈ 1.1% 年化成本
```

当年化超额仅 +0.10% 时，成本是超额的 11 倍。目标是将换手压到 5-8 倍附近，在合规范围内降低成本。

### 实现方案

在 `src/config.py` 中加入：

```python
OPT_TURNOVER_LAMBDA: float = 0.001  # 初始值，通过训练集网格搜索校准
```

在 `src/portfolio/optimizer.py` 的 L1 目标函数中加入换手惩罚：

```python
if w_prev_vec is not None and config.turnover_lambda > 0:
    turnover_penalty = config.turnover_lambda * cp.norm1(w_l1 - w_prev_vec)
    l1_objective = cp.Maximize(alpha_vec @ w_l1 - turnover_penalty)
else:
    l1_objective = cp.Maximize(alpha_vec @ w_l1)
```

**校准方法**：在**训练期**对 `[0.0005, 0.001, 0.002, 0.004]` 做网格搜索，找到让年化双边换手落在 5-10 倍的 `λ_TC` 值。验证期只跑一次对照，不根据验证期结果反向调整 `λ_TC`。

L1 范数保持问题凸性，与原 QP 一起用 CLARABEL/SCS 求解，不需要引入新求解器。

## 阶段 3：因子评价体系修正

> 详细方案见 `factor_evaluation_improvement_plan.md`

### 3.1 修改 Gate 2：lead_ratio 改为分级阈值（P0）

**当前**：lead_ratio > 1.0x 即拒绝（过严，`analyst_eps_revision`、`hk_hold_chg` 均被误杀）

**修改为**：
```
< 1.5x          → 通过
1.5x - 2.0x     → 警告，进入人工审议，不自动拒绝
> 2.0x          → 拒绝
```

预期将因子池从 6 个扩展到 8 个。

### 3.2 升级 Gate 4：验证期稳定性改为定量评分（P0）

| 验证期 IC_IR | 方向 | 处理 |
|------------|------|------|
| ≥ 0.2 | 一致 | 正常入池 |
| < 0.2 | 一致 | 权重减半，入池 |
| < 0.2 | 相反 | 警告标记，人工审议 |
| ≥ 0.2 | 相反 | 拒绝 |

**重要**：Gate 4 只用于最终报告，不循环用来决定因子进出。筛选依据是训练期内部子区间稳定性（见 3.4），验证期只报告结果。

### 3.3 加入覆盖率校正（P1）

IC 计算时，排除当期因子覆盖率 < 50% 的时间截面，避免覆盖率极低期间的噪声 IC 污染统计量。

### 3.4 加入子区间稳定性检验（P1）

把训练期切成 3-4 个子区间（每 2-3 年一段），分别计算 IC_IR，要求：
- 每个子区间 IC 方向一致（不能在某个子区间符号反转）
- 最差子区间的 IC_IR ≥ 整体 IC_IR × 50%

这是因子筛选的核心依据，比验证期单点检验更可靠，且不消耗验证集信息。

### 3.5 加入 IC Decay 检验（P1）

对每个因子计算对下 1、2、3、6、12 期收益的 IC，加入筛选标准：
- 好的月频因子：IC 在第 2-3 期仍保持原始 IC 的 50% 以上
- 问题因子：IC 在第 2 期接近零，信号极度短暂，月频换仓根本来不及捕捉
- **入池要求**：第 3 期 IC 仍为正值

### 3.6 加入 5 分组单调性筛选（P2）

当前 5 分组只展示，未作为硬性筛选标准。加入：Q5 > Q3 > Q1（对正向因子），至少保持粗粒度单调性。Q1 < Q3 < Q2 < Q4 < Q5 的因子在实际组合里大多数股票处于中间区间，使用效果远差于 IC 数字暗示的。

### 3.7 升级去冗余：加入偏相关检验（P2）

当前只做两两相关系数 > 0.70 去冗余，无法识别多因子联合重复信息。

升级：对每个候选因子做偏相关检验——控制所有已入选因子后，这个新因子还能额外解释多少收益？偏相关不显著则去掉。

## 阶段 4：低风险因子扩展

对现有因子做改进和变体，比引入全新因子风险更低。

### 4.1 财务因子时序平滑

用过去 3-4 个季度均值代替当期财务指标，去掉一次性事件干扰，表达"持续能力"。对 ROE、毛利率、ROA 效果显著。

```python
roe_smoothed_4q = (roe_q + roe_q1 + roe_q2 + roe_q3) / 4
```

### 4.2 因子动量（改善速度）

当期值与 N 期前的差，表达基本面变化方向，与绝对水平互补。

```python
roe_delta_3q   = roe_q - roe_q3      # ROE 改善速度（3 季度）
margin_trend   = gm_q - gm_q4        # 毛利率变化趋势
```

**注意**：需要至少 4 个季度历史数据，新上市股票和财务数据缺失时置 NaN。

### 4.3 相对历史估值

```python
ep_vs_history = ep_ttm_t / mean(ep_ttm, 过去 3 年)
```

表达相对于自身历史是贵了还是便宜了，与横截面排名互补。

### 5.3 因子工程：GARP 交叉因子（P1）

**注意**：不能用 `EP_zscore × ROE_zscore`——两个负值相乘得正，会把"既贵又差"的股票误判为好信号。

**正确实现方式（三选一）**：

```python
# 方式 A：rank 均值（推荐，最稳健）
garp = (ep_rank + roe_rank) / 2

# 方式 B：双重门槛（最直观）
garp = 1 if (ep_rank > 0.6 and roe_rank > 0.6) else 0

# 方式 C：min 运算（避免奖励双差股票）
garp = min(ep_rank, roe_rank)
```

### 5.4 因子数量控制

- **候选因子**总数控制在 **45 个以内**（BH 校正在此数量级保护效力合理）
- 经 IC 筛选后进入信号合成的因子控制在 **12-20 个**
- 每个新增因子必须有先于数据的经济假设，不做穷举组合

## 阶段 6：信号合成升级

### 6.1 将 alpha z-score 转换为预期超额收益

> 依据：`improve/optimizer_diagnosis.md` 问题 2

**问题**：目标函数 `max α^T·w` 中 α 是 z-score（无量纲），TE 约束是收益单位，量纲不匹配，优化器的配置行为没有经济含义。

**实现**（在 `src/signal/combiner.py` 输出后、优化器调用前）：

```python
# 预期月超额收益估计
# ic_mean：滚动历史 IC 均值（只用 < T 的窗口）
# vol_monthly：sqrt(diag(Σ_daily) × 21)，注意对极端高波动股票做截断
alpha_pred = ic_mean_composite * vol_monthly * alpha_zscore
```

**注意事项**：
- 高波动股票会被机械放大，需在转换后对 `alpha_pred` 做截面 winsorize
- `ic_mean` 的计算窗口严格 < T，不使用包含 T 日的窗口
- 建议在优化器小网格（阶段 1）完成且结果稳定后再引入此步骤

### 6.2 IC_IR 加权升级为 Ridge 回归（P1 of this phase）

Ridge 是当前数据量下信号合成最小有效升级：比 IC_IR 加权多正则化，防止单因子过度加权；比 XGBoost 所需数据量少，过拟合风险低；对框架改动最小，结果可解释。

**必须配合走验证**：

```
第 1 折：用 2012-2014 训练，在 2015 验证
第 2 折：用 2012-2015 训练，在 2016 验证
…（时间只能向前走，不允许随机 k 折）
```

正则化强度（alpha）通过走验证的验证集 IC_IR 选择，训练集与验证集之间留 **1-2 个月空窗（Purging）**。

**XGBoost 不纳入当前执行路线**：月频数据只有 108-132 个时间点，walk-forward 后有效训练窗口更短，过拟合风险高于收益，可作为独立后续实验。

## 禁止事项

| 操作 | 原因 |
|------|------|
| ✗ 换成周频调仓 | 财务因子季度更新，周频不增加有效信息；年化换手从 ~900% → 4000%+，成本翻 4 倍 |
| ✗ 使用深度学习 | 月频数据严重不足（需几千时间步，现有 108-132 个） |
| ✗ 穷举所有因子交叉组合 | 数据挖掘，过拟合风险随因子数量指数增长 |
| ✗ 用验证期结果反向调整因子进出 | 验证集过拟合，等同于用测试集调参 |
| ✗ 直接用数据库预计算财务因子 | PIT 处理逻辑未知，TTM 口径不统一 |
| ✗ 随机 k 折交叉验证 | 用未来数据训练，严重数据泄漏 |
| ✗ EP_zscore × ROE_zscore 作为 GARP | 双负值相乘得正，会奖励"既贵又差"的股票 |
| ✗ 替换 LedoitWolf 为样本协方差 | 反向操作，500 维样本协方差严重病态 |
