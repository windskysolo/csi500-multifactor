# 阶段 5：交易成本与成交约束诊断

生成日期：2026-05-21

本阶段只审查训练/验证公共产物，样本截止 2022-12-31；未运行正式测试集 Run #2，未使用 2023-2025 结果。

## 结论

交易成本会压低 V1/V2 的绝对收益，但不能解释 V2 为什么弱于 V1。2022 年 V2 的年化双边换手为 863.2%，低于 V1 的 898.9%；V2 成本合计为 1.09 个 NAV 点，也低于 V1 的 1.16 个 NAV 点。V2 相对 V1 少赚约 2.1 个 NAV 点，方向上与成本差异相反。

成交约束也不是主因。V2 全年只有 `n_locked=1`、`n_no_buy=6`、`n_no_price=2`、`n_no_sell=0`，数量较小；相对 V1 最差的 2022-03 持仓期没有任何成交约束触发，成本也只有 8.72 bps。

## 成本模型复核

2022 年全部交易日在 2023-08-28 印花税下调前，因此交易日志成本应满足：

`cost = sell_value * 0.001 + (sell_value + buy_value) * (0.00025 + 0.0008)`

复算结果：

| 版本 | 成本公式最大误差 |
|---|---:|
| V1 | 2.17e-19 |
| V2 | 2.17e-19 |

交易成本函数与配置一致：印花税卖出单边 10 bps、佣金双边各 2.5 bps、滑点双边各 8 bps。回测引擎使用 T+1 开盘执行，缺失状态保守设为 LOCKED；这部分没有发现能解释 V2 相对失败的明显口径错误。

关键观察：

- V2 相对 V1 最差的 2022-03 持仓期，成本仅 8.72 bps，且没有 `n_locked`、`n_no_buy`、`n_no_sell`、`n_no_price`。

## 成本对绝对收益的影响

V2 成本合计约 1.09 个 NAV 点，而 V2 年化超额为 -0.86%。这说明成本确实会影响绝对收益，甚至可能把一个很弱的毛超额压到负值附近。但这不是可优化掉的“错误成本”：

- 佣金、滑点和印花税是项目硬口径，不应为了改善结果而下调。
- V2 成本低于 V1，所以成本不能解释 V2 相对 V1 的劣势。
- 阶段 2-4 已显示信号 IC 衰减、IC_IR 加权拖累、优化压低 alpha 暴露，这些证据强于成本解释。

## 归因对账注意事项

本阶段主要采用交易日志直接复算成本。`attribution_nav_reconciliation.parquet` 可以作为辅助，但不应作为成本结论的唯一依据：

- 首个持仓期因为 NAV 起点问题存在 NaN。
- `attribution_metadata.json` 中 `reconciliation_max_excess_discrepancy` 为 `NaN`，严格 JSON 语义不佳。
- `attribution_metadata.json` 中 `backtest_weights_v2` hash 为 `e3b0c442`，疑似空输入 hash 或 hash 生成路径问题。
- 部分 `strategy_discrepancy` 为正，说明 NAV-Brinson 对账还混有期间端点、现金和几何链接差异，不能简单等同于成本拖累。

这些是报告产品化风险，但不改变本阶段主结论：直接交易日志显示成本与成交约束不是 V2 相对 V1 表现差的主因。

## 产品化判断

阶段 5 通过成本合理性审查，但不通过“成本解释策略失败”的假设。成本是二级问题，下一轮改进不应优先调交易成本或换手惩罚，而应优先处理信号合成、因子稳定性和优化后的 alpha 暴露。

## 下一步建议

1. 把月度 `turnover`、`cost_bps`、`n_locked`、`n_no_buy`、`n_no_sell`、`n_no_price` 固定写入发布报告，避免只展示净值。
2. 做 pre-cost / post-cost 对照只作为披露，不用于选择成本参数。
3. 后续若改优化器，应同时记录 alpha exposure 与成本变化，防止用更低换手换来更低 alpha。
4. 修复归因 metadata 的 `NaN` 与疑似空 hash，再进入最终归因报告阶段。
