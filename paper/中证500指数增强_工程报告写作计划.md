## 一、摘要

> 💡 **写作提示**：最后写这一节，等全文写完再提炼。控制在 200 字以内，覆盖：目标、方法、结果、核心发现、后续状态。

本项目构建了一套针对中证500指数的量化增强选股策略。核心方法为 Rolling 48个月 Ridge 信号 + TopN150 等权组合 + hk_hold 季度因子，在验证期（2021-2022年）实现信息比率（IR）2.150、年化超额收益 9.35%、超额最大回撤 −3.03%、年化换手率 722%，各项指标均通过预设的三项硬指标门槛（IR ≥ 0.5，超额 MDD ≤ 10%，换手率 500%–1500%）。测试期（2023-2025年）首次评估 IR=0.645，三项硬指标全 PASS。

研究中发现 QP 优化器对 Ridge 信号存在系统性 IR 损耗（-0.166 ~ -0.431），根因已诊断为"基数信号 vs 序数选股"的结构性不匹配，最终采用 TopN EW 路线。消融实验显示 piotroski_f 移除后 IR 改善，因子集存在进一步精炼空间。

## 二、项目背景与目标

> 💡 **写作提示**：约 300 字。回答三个问题：为什么做指数增强、为什么选中证500、目标怎么量化。

### 2.1 指数增强策略的价值

指数增强策略在严格控制相对基准的跟踪误差的前提下，通过量化选股挖掘超额收益（alpha）。与纯主动管理相比，它具有风险来源清晰、可归因、容量较大的优点；与纯被动复制相比，它在可接受的风险预算内寻求超越基准的回报。

### 2.2 选择中证500指数的原因

中证500成分股覆盖 A 股中市值区间的中盘股，成分股数量适中（500只），个股流动性相对充裕，行业分布较为均衡，且相比沪深300信息不对称程度更高，为量化选股模型提供了更大的 alpha 挖掘空间。

### 2.3 量化目标

本项目设定三项硬性绩效指标作为方案晋升的必要条件：

| 指标 | 目标阈值 | 设定依据 |
|---|---|---|
| 信息比率（IR） | ≥ 0.5 | 超额收益稳定性的基准要求 |
| 超额最大回撤（MDD） | ≤ 10% | 控制策略相对基准的最大回撤风险 |
| 年化换手率 | 500% – 1500% | 兼顾 alpha 捕捉频率与交易成本 |

## 三、系统整体架构

> 💡 **写作提示**：约 500 字 + 架构图。直接引用 A1 文档中的分层图，配简短的逐层说明。重点写三个关键设计决策的"为什么"，不需要写具体函数。

### 3.1 九层架构总览

系统由九层组成，依赖关系严格单向向上，每层只能调用同层或下方层的模块：

```
Layer 8  Pipeline 编排层     实验入口与编排
Layer 7  实验入口脚本层      run_experiment / compare_runs / promote_run
Layer 6  归因层              Brinson 行业归因 / 因子收益归因
Layer 5  回测层              回测引擎 / 交易成本 / 绩效指标
Layer 4  组合构建层          协方差估计 + 二次规划（QP路径）/ TopN等权（EW路径）
Layer 3  信号合成层          IC_IR加权 / Ridge / Decay Ridge 三条路径
Layer 2  单因子评估层        IC分析 / 因子健康度 / 五分组回测 / 时间错位检验
Layer 1  因子构建层          财务因子 / 量价因子 / 备选数据因子 / 预处理
Layer 0  数据基础层          统一读取接口 / PIT快照 / 可投资域管理
```

### 3.2 三个关键设计决策

**决策一：Stage 编排与业务逻辑分离**

`pipeline/stages.py` 只负责根据实验配置选择正确的实现路径，以及对齐输入/输出路径，不包含任何金融计算逻辑。这样底层模块（如信号合成）可以被独立测试，修改算法只需改对应的 `src/` 模块，不影响编排层。

**决策二：用 Python 文件定义实验配置（ExperimentSpec）**

`configs/pipelines/` 下每个实验对应一个 `.py` 文件，而非 YAML/JSON。原因是 Python dataclass 可在加载时进行类型校验，IDE 可检查字段名，`__post_init__()` 可在加载时立即执行测试集保护锁等逻辑。

**决策三：PIT 正确性的中央保证**

财务数据的 Point-in-Time（PIT）正确性由 `pit_loader.py` 的 `_filter_visible()` 统一保证，采用双重过滤（`pit_date ≤ T` 且 `end_date < T`）。因子层函数接收到的数据已是 PIT 安全的，无需再次过滤，防止前视偏差（look-ahead bias）。

| 测试期 | 2023-01-01 ~ 2025-12-31 | 最终评估，全项目生命周期最多运行 3 次 |

## 五、因子体系

> 💡 **写作提示**：约 600 字。用准备清单③整理好的因子表。重点讲五步预处理和四道Gate的设计逻辑，因子列表附在后面。

### 5.1 因子库构成

系统共构建三大类候选因子：

**财务因子**（最终入选 10 个）：涵盖盈利质量（`q_roe`、`roe_delta`、`roe_delta_3q`）、成长性（`rev_yoy`、`rev_acceleration`）、估值（`ep_ttm`、`cfp`）、利润率趋势（`gross_margin`、`gross_margin_trend`）、质量复合因子（`piotroski_f`，REMOVE_CANDIDATE）。所有财务因子均使用 TTM 口径，以 `f_ann_date`（公告日期）为 PIT 锚点。

**量价因子**（最终入选 5 个）：流动性（`turn_20d`、`amihud`）、波动率（`ivol_60d`）、动量（`high_52w_v2`）、持仓变化（`holder_chg`）。

**备选数据因子（约 12 个）**：包括港股持仓类因子（`hk_hold_ratio`、`hk_hold_chg`）、分析师一致预期等。其中 `hk_hold_ratio` / `hk_hold_chg` 为季度 PIT 快照因子（270 日回望 + 10 日偏移 + 120 日滞后保护），捕捉北向资金持仓偏好；修复 P0 空月 bug（原实现导致 2021-2022 年全空）后，引入该类因子使主线 IR 从 1.771 提升至 2.150。

### 5.2 五步预处理流水线

每个因子在每个调仓日均经过以下横截面处理：

1. **可投资域过滤**：剔除停牌、涨跌停、ST 个股，仅保留中证500成分股
2. **MAD 去极值**：将超出中位数 ±3 倍绝对偏差的值截断至边界，减少异常值影响
3. **Z-score 标准化**：横截面标准化，使因子值具有可比性
4. **行业与市值中性化**：对申万一级行业和自由流通市值对数做截面回归，取残差，消除系统性风格暴露
5. **再标准化**：对中性化后的残差再次 Z-score，确保最终输入信号合成的数值分布稳定

### 5.3 四道 Gate 筛选

对预处理后的因子时序，通过以下四道评估门来决定是否纳入最终因子集：

| Gate | 评估指标 | 说明 |
|---|---|---|
| Gate 1 覆盖率 | 横截面有效值比例 | 覆盖率过低的因子信息量不足 |
| Gate 2 IC_IR | 历史 IC 均值 / IC 标准差 | 衡量因子预测能力的稳定性 |
| Gate 3 单调性 | 五分组收益的单调程度 | 验证因子分层有效性 |
| Gate 4 方向一致性 | IC 符号稳定性 | 防止因子方向在时间序列上频繁翻转 |

### 6.2 路径 A：IC_IR 加权（冻结基线）

IC_IR 加权方法在每个调仓日使用过去 24 个月的 IC 历史，以各因子的 IC_IR 作为权重线性合成综合信号。该方法无需训练过程，实现简单，在 TopN 等权优化器搭配下 IR 达到 0.924，构成项目的冻结基线。其局限在于因子权重静态依赖历史 IC_IR，无法捕捉因子间的交叉效应与收益的非线性结构。

### 6.3 路径 B：Ridge 回归（当前主线）

Ridge 回归将因子值矩阵作为特征，未来一期收益作为目标，使用 L2 正则化防止过拟合，通过回归系数实现因子加权合成。

**训练窗口的选择**：expanding（全历史）窗口在早期样本量有限时权重分散，对市场环境变化的适应性较弱。rolling 窗口通过固定训练长度使模型聚焦于近期规律。实验结果表明，rolling 48 个月窗口在信号稳定性与对近期市场的适应性之间取得最优平衡（IR=1.489），显著优于 expanding 方案（IR=0.408）。

**Walk-forward 防数据泄露**：训练样本与预测期之间设置 `purge_months=2` 的间隔，避免训练数据包含调仓日附近的价格信息，防止数据泄露。

### 6.4 路径 C：Decay Ridge（探索方向）

Decay Ridge 在 expanding 窗口基础上引入指数衰减权重，使近期样本获得更高权重。实验结果显示，较短半衰期（hl=24，IR=0.626）具有一定效果，但半衰期增大后（hl=36/48）IR 降至 0.295/0.289，未通过 IR 门槛。推测原因是半衰期过长时衰减效果趋近于 expanding，失去引入衰减的意义；而过短则导致训练样本有效信息量过少，信号方差增大。该路径整体表现不及 rolling 窗口方案，未纳入主线。

## 七、组合构建与优化

> 💡 **写作提示**：约 600 字。用准备清单⑤的损耗数据。核心是 QP 损耗这个发现，要给出具体数字支撑并提出根因假设。

### 7.1 两条组合构建路径

**QP 路径（二次规划）**：使用 LedoitWolf 方法估计 24 个月历史收益的协方差矩阵，通过 cvxpy 求解二次规划问题，施加以下约束：
- 跟踪误差 TE ≤ 6%（年化）
- 行业偏离 ≤ 3%（相对基准）
- 单股权重偏离 ≤ 1.5%

当 QP 求解失败时，依次降级至 L2（线性约束）→ L3（TopN 等权）的 Fallback 机制，保证每个调仓日均能产出权重。

**TopN EW 路径（等权）**：按合成信号排名取前 N 只股票等权持有（当前主线 N=150），不调用协方差估计，不依赖 cvxpy。设计目的最初是**隔离优化器影响**，用于诊断 QP 损耗；最终实验证明 TopN EW 在所有信号类型上均优于 QP，已成为正式主线路径。

### 7.2 关键发现：QP 优化器对 IR 的系统性损耗

> 💡 **写作提示**：将准备清单⑤的损耗表格粘贴于此，配以下段落。

| 信号类型 | TopN EW IR | QP IR | 损耗（EW−QP） | 损耗% |
|---|---|---|---|---|
| IC_IR 信号 + TopN50 | 0.924 | 0.408（expanding+QP） | −0.516 | −56% |
| expanding Ridge + TopN50 | 0.574 | 0.408 | −0.166 | −29% |
| rolling48 Ridge + TopN50 | 1.771 | 1.489 | −0.282 | −16% |
| rolling48 Ridge + TopN150 + hk_hold | **2.150** | — | — | — |

实验结果显示，**QP 优化器对所有 Ridge 信号均造成 IR 损耗，幅度在 -0.166 至 -0.431 之间**。以 rolling48 为例，TopN EW 下 IR=1.771，QP 下 IR=1.489，损耗 0.282。这一现象在不同训练窗口的 Ridge 方案中均一致出现，说明问题来自优化器本身而非特定信号设置。

**根因已诊断（2026-05-29）**：松 TE / 松行业约束均使 QP 变差，说明约束本身是保护机制而非阻力。真正瓶颈是"基数 vs 序数"的结构性问题——QP 使用 alpha 绝对量级分配权重，对信号噪声敏感；TopN EW 仅使用 alpha 排名，对噪声更鲁棒。排名变换 QP 实验（IR=0.299）明确证伪了"通过改变信号形式修复 QP"的假设，最终确认 TopN EW 路线为正式方案。

> 💡 **写作提示**：将准备清单⑤的损耗表格粘贴于此，按上述根因结论补充分析段落。

## 八、实验治理体系

> 💡 **写作提示**：约 400 字。说明五类实验角色和晋升流程。这一节体现工程严谨性，不要省略，但也不要过度展开代码细节。

### 8.1 五类实验角色

系统将所有实验按职责分为五类，实现严格的角色隔离：

| 角色 | 命名前缀 | 职责 |
|---|---|---|
| 冻结基线（frozen_baseline） | `frozen_baseline_*` | 永不重跑的绝对对照锚，用于验证是否有绝对改进 |
| 主线基线（baseline） | `baseline_*` | 当前被认可的生产方案，是 challenger 的比较对象 |
| 挑战者（challenger） | `challenger_*` | 待验证的新方案，需超越主线基线才有晋升意义 |
| 消融实验（ablation） | `ablation_*` | 一次只改一个变量，量化单个因子或模块的净贡献 |
| 测试集运行（test_run） | `period_scope="test_run_N"` | 最终评估，全项目最多 3 次 |

**冻结基线**（`frozen_baseline_icir_topn50_ew`，IR=0.924）永不重跑、永不晋升，作为固定参照消除数据区间扩展对 IR 的正向影响。

### 8.2 实验晋升流程

挑战者方案通过三项硬指标全部 PASS 后，才可通过 `promote_run.py` 写入 `registry/mainline.json`，成为新的主线方案：

```
新实验 → 三项硬指标评估（IR ≥ 0.5 / 超额 MDD ≤ 10% / 换手率 500%-1500%）
    → 全 PASS → promote_run.py → mainline.json（更新主线）
    → 任一 FAIL → 记录结论 → 更新 challengers.json
```

所有实验结果的横向比较通过 `compare_runs.py` 生成 `experiment_board.md`，必须包含冻结基线作为下限参照。

### 8.3 测试集纪律

测试集（2023-2025年）全项目生命周期最多运行 3 次，权威计数由 `docs/logs/test_set_runs.json` 维护。**当前已用 1 次，剩余 2 次。** [TEST_SET_RUN_1] 于 2026-06-02 完成：测试期 IR=0.645（PASS）、超额 MDD=5.70%（PASS）、换手 728%（PASS），三项硬指标全 PASS。这一约束的目的是防止因多次查看测试集结果而产生隐式过拟合，保证最终评估的客观性。
